# Windows采集端与自研存储服务详细设计

## 1. 自研范围与接口边界

自行开发Agent、上传会话管理、文件验证与存储目录管理、资产元数据、访问授权、下载接口、卷管理、迁移/备份编排、运维界面。首版使用操作系统文件系统保存字节、PostgreSQL保存服务端元数据、SQLite保存Agent本地队列。

不自行实现物理文件系统、RAID、TLS、SSH或通用DICOM解码器。Windows服务封装和HTTP库可以复用成熟组件。以前建议的tusd可作协议实现参考，不作为本版必须依赖；本版拟议分片协议由我们实现，不能宣称兼容tus。

Agent不需要HIS数据库密码。它主要知道设备、采集根目录、文件ID、原始条码及传输身份；患者关联在服务器完成。存储服务只知道授权的租户/资产/文件，不理解病理号含义。

## 2. Agent进程与本地数据

Windows后台服务负责采集和传输；托盘程序/本机状态页只展示服务状态与授权操作，普通用户关闭界面不影响服务。安装时创建专用低权限服务身份；本地队列、证书和配置保存在受ACL保护的数据目录，路径由安装配置明确。

模块：DeviceEnrollment、ConfigurationManager、DiscoveryScanner、CompletionDetector、ManifestBuilder、TransferWorker、InventoryReconciler、HealthReporter、LocalAudit、Updater。

| SQLite表 | 必需字段/约束 |
|---|---|
| agent_identity | agent_id、tenant_id、证书指纹、注册时间、配置版本；不保存明文长期注册令牌 |
| watched_root | root_id、规范化路径、递归策略、文件过滤、启用状态、最近全盘点时间 |
| discovery_entry | entry_id、root_id、相对路径、文件系统身份（如可得）、大小、mtime、发现/扫描批次、generation；路径不是唯一身份 |
| acquisition_event | event_id、source_event_id、source_revision、清单JSON、完成证据、状态；重复厂商事件唯一 |
| transfer_local | transfer_id、asset_id、session_id、session_epoch、文件快照、总片数、状态、重试时间 |
| chunk_local | transfer_id、chunk_index、大小、hash、服务端已确认时间；唯一(transfer_id,index) |
| command_inbox | command_id、类型、配置版本、接收/执行结果；按ID幂等 |
| local_issue | 分类、对象、错误摘要、首次/最后发生、下一步动作 |

SQLite采用事务和WAL，恢复时做完整性检查，数据库损坏不能直接清空后从头上传；保留故障副本并通过重新盘点和服务器事件查询恢复。服务重启重放未完成状态，不能生成新的采集事件ID冒充新扫描。

## 3. 发现、完成、文件快照

### 3.1 三种采集模式

1. **厂家完成接口模式**：轮询扫描任务变更或接收完成通知；通知只是提示，随后查询权威清单并获取文件。支持从持久游标补拉。
2. **厂家manifest模式**：厂家在全部文件关闭后，先写清单临时文件，再原子改名为完成清单；我方按清单识别玻片/扫描版本/成员。
3. **目录模式**：watch事件＋启动盘点＋周期盘点；按医院设备Profile识别目录和文件。没有可靠完成信号时只进入候选，人工或PIS/厂商确认后放行。

本版不假设厂商具备上述任一接口；06是拟议要求。目录模式可先做，但真实目录、排除规则、文件格式、多文件拓扑须现场确认。

### 3.2 文件稳定不等于扫描完成

建议记录 `completion_method、observed_at、vendor_task_state、manifest_revision、size/mtime_samples、validation_result、operator_id`。独占打开、60/120秒稳定窗口、格式可读均只是证据之一，不能证明厂家不会再次写入。

可用厂家完成事件时仍检查成员清单、长度和传输期间变化。不可用时建议复制至本机受控spool形成稳定快照；复制前后源属性变化则废弃该次spool，继续等待。属性未变仍不能绝对证明内容未被原地修改；最终需要厂家提供不可变文件承诺或人工放行。不能悄悄把启发式模式升级成“自动可靠模式”。

支持厂商只读快照/API对象版本时，以版本和ETag/摘要取得不可变内容。源文件被改写、删除或同路径替换后形成新的generation；相同文件重命名可通过可用文件身份和内容证据关联，但不要把路径hash当全局唯一ID。

### 3.3 多文件集合与清单

集合包含唯一bundle_id、revision、成员asset_id、role、relative_path、size_bytes、sha256和依赖关系。成员角色至少支持primary、index、tile_data、label、thumbnail、metadata、report、other。相对路径保留层级，禁止绝对路径、`..`、设备路径、符号链接/重解析点越界、大小写归一后冲突和Windows保留文件名。

服务端计算清单摘要使用确定性的序列化规则：UTF-8、成员按标准化相对路径排序、固定字段、排除可变化签名URL；同一清单ID内容变化返回冲突。业务病理号保持原值，不把文件路径标准化规则作用于病理号。

## 4. 我方分片上传协议 v1

### 4.1 身份与会话

Agent一次性注册令牌只能申请设备证书/服务凭据，随后使用短期令牌或mTLS；租户从认证上下文推导，服务端忽略客户端对其他租户的声明。注册、证书轮换、吊销和设备停用留审计。

先提交acquisition manifest，再为各资产创建UploadSession。创建请求带稳定Idempotency-Key和预期size/hash；相同key不同内容返回409。返回session_id、asset_id、chunk_size、chunk_count、有效期、session_epoch及已存在会话信息。

默认建议64MiB分片、每Agent并行2个文件、每文件1—2片；均可下调，生产以扫描磁盘负载实测为准。所有长度使用64位整数，文件大小单位固定字节，空文件只有业务类型允许时才能接收。

### 4.2 请求序列

| 步骤 | 接口（我方拟议） | 行为 |
|---|---|---|
| 登记 | POST `/api/v1/acquisitions` | 持久化清单，返回acquisition_id及资产计划；重复事件返回同一资源 |
| 建会话 | POST `/api/v1/upload-sessions` | 配额预留，返回固定分片策略和会话 |
| 查进度 | GET `/api/v1/upload-sessions/{id}` | 返回状态、已完成分片索引/摘要及分页信息；服务端进度为准 |
| 传分片 | PUT `/api/v1/upload-sessions/{id}/chunks/{index}` | 二进制body；Content-Length及X-Chunk-SHA256；固定索引隐含字节偏移 |
| 完成 | POST `/api/v1/upload-sessions/{id}/complete` | 校验所有分片齐；进入VERIFYING，返回202及operation_id |
| 查结果 | GET `/api/v1/operations/{id}` | 最终返回可用资产或错误；不能把202当归档成功 |
| 取消 | DELETE `/api/v1/upload-sessions/{id}` | 取消尚未提交会话；异步释放临时内容与配额 |

每片接收时流式计算SHA-256并写临时片，校验通过后fsync/适用持久化操作、原子发布该片，再事务登记ACK；同一index同hash重试返回成功，同index不同hash返回409且不覆盖。缺失片complete返回409和缺片列表；超出索引、错误长度、超限内容分别400/422/413；限流429加Retry-After。

采用“单会话单落盘节点归属”。若未来多个storage节点共享同一会话，必须实现互斥/租约和fencing epoch；旧节点不得在新epoch继续写入。首版不宣称跨节点接管，服务重启在原卷恢复即可。

### 4.3 重试和恢复

网络错误、429及可恢复5xx指数退避＋抖动；认证过期刷新后重试，403/配置错误转人工；会话过期410后与服务端核对已有资产，再按同一采集事件重建会话。重建会话不创建新扫描版本。

分片数据未收到ACK时先查询服务端或直接幂等重传；不据本地“已发送”认定成功。chunk_local只在服务器确认后写已完成。complete重复调用返回同一operation_id或同一最终资产，不触发重复合并。

## 5. 存储持久化与崩溃一致性

首版目录布局建议：`volumes/{volume_id}/staging/{session_id}/chunks`、`.../assembling/{asset_id}.tmp`、`.../objects/{prefix}/{blob_id}`、`.../quarantine/{id}`。目录名由服务生成，不接受客户端提供物理路径。正式文件不可变。

流程：检查配额和磁盘水位；收到全部片后按索引顺序流式合并并计算整文件hash；大小/hash匹配后将临时文件在同一卷原子改名为正式blob；完成适用持久化同步后，事务将blob置AVAILABLE并建立asset_location、写Outbox。Windows/Linux的rename与同步行为须按目标存储实测；网络共享不能未经验证套用本地文件系统保证。

合并与分片同时存在时，峰值磁盘占用接近原始文件的2倍，再加并行会话与派生任务。因此预留大小应计入最坏临时空间，而非仅预留N字节。可在后续版本优化为安全的预分配随机写入，首版不混用两种实现增加风险。

| 崩溃点 | 恢复行为 |
|---|---|
| 分片已写未登记 | 重启扫描会话目录，验证对应片后补登记或删除无效片；幂等重传不能覆盖冲突片 |
| 全片齐但未合并 | Job回收租约后重新合并，保留原operation_id |
| 合并途中 | 临时合并文件不能下载；清理/重建临时文件，不碰已确认分片 |
| blob已落盘、DB未提交 | 使用提交意图记录/asset_id恢复事务；无有效意图则隔离待核对 |
| DB已可用但文件不存在/损坏 | 标UNAVAILABLE/QUARANTINED，阻止发布和下载，尝试副本恢复 |
| DB/存储短时不可用 | 不向Agent返回最终持久化成功；保留会话和文件继续恢复 |

不追求跨DB/文件系统原子事务，依靠状态、幂等、提交意图、Outbox和盘点恢复。文件成功存储不代表已完成备份；UI分别展示primary_durable、replica_verified、backup_verified。

## 6. Blob、Asset、Bundle与去重

Blob表示字节内容，Asset表示业务可引用的文件实体，Bundle表示一次扫描/格式的文件集合。相同字节可以对应多个Asset，保留不同来源事件及玻片关系。首版可不开物理去重，先确保语义正确；启用后限定同租户内按 `(sha256,size)` 查重，不向未授权用户暴露别的租户是否已有内容。

上传端本机hash用于预告，服务器必须自己验证。不能只信客户端hash就把未授权已有文件返回给客户端；复用必须经过资产授权与来源登记流程。

格式解析失败与传输损坏分开：未知格式可归集AVAILABLE但metadata_state=UNSUPPORTED；hash失败为QUARANTINED；目标Profile需要预览/解码时在发布校验中阻断。缩略图失败不应删除原件。

## 7. 下载与对外文件服务

内部下载使用asset_id，先鉴权再解析位置。交换下载使用publication_id和publication_item_id，只允许访问该发布快照授权的固定资产版本；不能映射到“最新玻片文件”而悄悄改变字节。

支持HEAD、GET、单段Range、206、416、Content-Length、Content-Range、Accept-Ranges和稳定ETag；If-Range不匹配时按HTTP语义发送完整响应。多段Range首版可按标准忽略并返回完整200，不实现自创的拼接格式。采用流式输出，限制并发、总带宽和请求时间，客户端断开及时释放句柄。依据[HTTP语义RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html)实现并做协议测试。

预签名链接只用于短时内部操作。若采集器仅能读取长期URL，提供稳定受控下载端点，并采用平台支持的mTLS、认证头、专网访问控制或约定的专用凭据。不能把内部短期token反复填进长期发布视图；鉴权方式未知则阻断生产下载配置。

记录每次访问的目标账号、资产版本、时间、范围、传输字节、结果和中断状态。一次完整GET完成仅标记DELIVERY_OBSERVED；多个Range的字节并集可形成传输证据，但仍不能证明对方校验或业务接受。

UI禁止把完整下载URL中的令牌展示到普通日志。下载文件名做响应头转义；Label/缩略图可能含患者信息，与原图一样授权。

## 8. 自研存储管理能力

存储卷状态：ACTIVE、DRAINING、READ_ONLY、OFFLINE。每卷保存路径/后端、容量、保留水位、挂载探测、租户配额及健康状态。探测必须验证真实挂载，防止NAS卸载后误写系统盘同名空目录。

容量预留由数据库事务锁定，不能所有工作站同时通过磁盘检查后把盘写满。低水位停止新会话、保留已有任务恢复空间并告警；不删除未归集源文件腾空间。大容量文件校验走限速后台任务，不占用核心API请求线程。

迁移：创建目标副本→完整hash校验→事务切换主位置→保留旧位置至在途读取结束和安全窗口届满→回收。资产ID和已发布URL不变。引用表决定是否可删除；提交/发布快照、保留锁、备份任务存在时不得删除。

垃圾回收采用mark-and-sweep：先标记无引用候选、显示原因/保留期，二次确认引用及任务后删除。业务取消只改状态/对外墓碑，不等同于立即物理删除。

定期任务：暂存过期回收、孤立文件核对、抽样/全量hash巡检、磁盘容量预测、副本检查、备份检查。单机文件系统不是分布式存储，不承诺多机一致性或自动容灾；以后StorageBackend可接院内NAS/S3，继续由我方服务提供统一权限与资产语义。

## 9. 设备配置、更新与源文件保留

控制台发布不可变Agent配置版本；Agent先校验路径、权限和规则，再ACK应用。失败保持上一个可用版本。正在上传的会话绑定旧传输策略，新配置影响新任务，不中途改变分片大小。

命令限于应用配置、暂停/恢复、触发盘点、有限诊断包、升级；每个命令有ID、有效期和审计，不提供远程shell。升级包验证签名/hash、版本兼容和本地队列备份；升级失败回滚二进制，数据库迁移须向后兼容或有明确恢复步骤。

源文件自动删除首版关闭。后续启用必须具备医院授权、服务器原件可用、备份/副本条件、保留期、无未解决版本冲突和完整清理审计。即便医保确认，也不能绕过院内留存要求。

## 10. 性能与故障验收

断网在任意分片、ACK丢失、磁盘满、卷离线、进程被杀、系统重启、同会话并发重试、同名改写、hash不符、路径穿越、连接吊销均需注入测试。实测记录CPU、RSS、磁盘读写、吞吐和扫描软件响应；不能只测试空闲服务器拷贝速度。

示例容量模型延续v0.2：200例×8片×0.5GB=800GB/日，另计重扫、分片临时空间、衍生与备份。实际采购需采样真实格式大小分布、设备数量、峰值时段与保留期限。
