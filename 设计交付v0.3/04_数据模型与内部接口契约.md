# 数据模型与内部接口契约

本章为我方系统开发契约，不是医保或厂商现有接口。所有外部字段通过Profile映射，不要求HIS/PIS按内部命名改库。

## 1. 数据约定

- 内部ID使用UUID，外部标识均字符串；不把外部标识转整数，不移除前导零。
- 所有业务表带tenant_id；子表采用 `(tenant_id,parent_id)` 外键并给父表该组合唯一约束，防止跨租户串联。即使首版单院也不移除租户约束。
- 系统事件时间用带时区时间戳，UTC保存、Asia/Shanghai显示；原系统无时区时间保留原始值及解释时区。业务日期与事件时间分开。
- 金额与计量用Decimal，API采用精确十进制字符串，例如 `"12.50"`，禁止浮点计算收费。
- 文件长度用BIGINT，SHA-256为64个小写十六进制字符；原件与衍生各自hash。
- 可变配置/主实体使用row_version乐观锁；不可变数据包修订、提交快照和发布快照不提供UPDATE内容API。
- 核心约束用关系字段；非关键领域扩展放受版本Schema约束的JSONB。不得仅把全部数据塞在无索引JSON中。
- 敏感字段加密或采用医院批准的存储保护；查询匹配索引使用密钥化摘要而非公开hash，日志不包含原证件和完整索引。

## 3. 并发和增量一致性

任务领取用短事务、行锁与租约；PostgreSQL可用 `FOR UPDATE SKIP LOCKED` 领取队列任务，领取后提交事务，网络调用在事务外执行。完成时校验lease_epoch及row_version，不能持有数据库锁等待大文件传输。参考[PostgreSQL SELECT文档](https://www.postgresql.org/docs/current/sql-select.html)。

外部副作用前持久化发送意图与稳定幂等键。执行进程在发出请求后崩溃，恢复进入UNKNOWN并查询远端；不能因为租约过期就创建新的提交。接收方不支持幂等/查询时，必须以证据对账或人工处理，不能承诺恰好一次。

源数据库增量推荐 `(last_change_time, stable_primary_key)` 游标＋重叠回看，固定本轮watermark以免遍历期间无限增长。时间回拨、低精度时间戳、补录早期记录、物理删除用周期全量/窗口盘点补偿；源无可靠变更字段时不得宣称增量完整。

轮询页的原始记录与checkpoint同事务持久化后才ACK源游标；后续治理失败不阻断源采集，但记录质量异常。相同游标消息重复到达不产生重复业务修订。

## 4. 内部API共同约定

前缀 `/api/v1`；HTTPS；JSON UTF-8；分页使用cursor和limit（默认50、上限200）。请求带X-Request-ID，服务生成trace_id；写入具副作用接口支持Idempotency-Key，资源更新要求If-Match/row_version。缺少前置版本返回428，版本冲突412。

认证主体分用户、Agent、Connector、Collector。tenant_id从认证上下文取得，跨租户操作需明确授权。所有外部提供的source、asset和parent ID均校验租户与对象权限。

JSON成功响应统一 `{ "data": ..., "request_id": "..." }`；异步返回202和operation_id；二进制上传/下载不包JSON。错误返回 `{ "error": {"code":"...","message":"...","retryable":false,"field_errors":[],"details_ref":null}, "request_id":"..." }`，不回显数据库连接串、令牌或患者敏感值。

同一主体/路由的Idempotency-Key绑定请求规范化摘要和业务结果；不同内容返回409。同一长期业务操作优先靠领域唯一键永久去重，API幂等缓存即使到期也不得破坏该约束。

## 6. 关键状态表

| 对象 | 允许的主路径 | 分支与不变量 |
|---|---|---|
| UploadSession | CREATED→RECEIVING→VERIFYING→COMPLETED | 可ABORTED/EXPIRED/FAILED；COMPLETED不回到RECEIVING |
| Asset | STAGING→VERIFYING→AVAILABLE | 可QUARANTINED/UNAVAILABLE；AVAILABLE字节不可变 |
| PackageRevision | DRAFT→VALIDATING→VALIDATED→FROZEN | 可WAITING/INVALID；FROZEN后改动产生新revision |
| StepRun | PENDING→READY→RUNNING→SUCCEEDED | 可WAITING_EXTERNAL/WAITING_HUMAN/RETRY_WAIT/FAILED/CANCELLED；成功输出引用不可变 |
| Submission | PREPARED→SENDING→ACCEPTED→CONFIRMED | PARTIAL/REJECTED/UNKNOWN；远端确认必须有证据 |
| Publication | PREPARING→READY→PUBLISHED | READY要求字节可达；可SUPERSEDED/REVOKED；PUBLISHED不等于CONFIRMED |
| DeliveryEvidence | NONE→PARTIAL→COMPLETE_OBSERVED | 仅网络传输观察结果；与BusinessConfirmation独立 |

状态变化由服务层集中命令执行，带expected_state/row_version及audit，不允许接口随意PATCH state。来自远端的较旧回执保存但不回退较新业务版本；处理顺序按平台版本/关联信息，不能只比较本地接收时间。

## 7. 错误分类

| code | 自动重试 | 处置 |
|---|---|---|
| SOURCE_UNAVAILABLE / NETWORK_TIMEOUT | 是，有限退避 | 不丢checkpoint；超阈值告警 |
| SOURCE_AMBIGUOUS / IDENTITY_CONFLICT | 否 | 业务复核 |
| REQUIRED_FIELD_MISSING / DICTIONARY_UNMAPPED | 等待数据或配置修复 | 标记field_path与规则版本 |
| SOURCE_FILE_CHANGED | 重新采集快照 | 不延用旧预期hash |
| CHUNK_HASH_MISMATCH / FILE_HASH_MISMATCH | 可重传，有限次数 | 隔离，不发布 |
| STORAGE_CAPACITY_LOW / VOLUME_OFFLINE | 等待恢复 | 背压，禁止删未归集原件 |
| IDEMPOTENCY_CONFLICT / VERSION_CONFLICT | 否 | 返回409/412并展示差异 |
| CAPABILITY_UNSUPPORTED / PROFILE_UNAPPROVED | 否 | 阻断生产，不返回假成功 |
| REMOTE_REJECTED | 按业务错误分类 | 数据更正产生新提交 |
| REMOTE_RESULT_UNKNOWN | 先查询/对账 | 不盲目创建新业务提交 |

## 8. 查询与索引要求

为(tenant,state,next_retry/available_at)、(tenant,source_system,external_id)、(tenant,pathology_no)、(tenant,created_at)、(tenant,destination,state)、(session_id,index)、(blob_id,location_state)建立索引。大审计/访问记录按时间分区或归档，任务正文只存小引用，禁止存文件Base64。

应用角色不得直接修改审计或通过普通业务账号创建外部视图。迁移由独立部署角色执行。所有表变更通过迁移脚本，禁止现场手动改库后不回写版本管理。
