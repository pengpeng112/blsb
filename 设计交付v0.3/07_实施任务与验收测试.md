# 实施任务、测试与交付标准

## 1. 实施原则

按纵向闭环交付，每阶段都有可运行结果。先做可恢复字节归集，再做病理关联和可视化流程，随后适配真实外部平台。首期不同时实现所有数据库驱动、所有WSI解码和所有医保协议。

生产上报的等待项仅阻断对应外部契约，不能成为不做本地MVP的理由。所有Mock、草案Profile和未实现适配器显著标识；测试环境和生产目标分开配置。

## 3. 开发任务分解

| 任务 | 依赖 | 应交付 | 完成判定 |
|---|---|---|---|
| T01 基础工程 | 无 | 目录、配置、日志、健康检查、迁移、CI、开发环境 | 新环境按README启动并自动迁移 |
| T02 契约与权限 | T01 | Schema、错误码、主体/租户授权、幂等中间层 | 越权/同键不同请求被拒绝 |
| T03 自研Storage v1 | T02 | 会话、分片、合并、hash、下载、操作查询、卷预留 | 任意分片断网重启可恢复，不产生假AVAILABLE |
| T04 Agent v1 | T02/T03 | Windows服务、SQLite、目录盘点、清单、传输、心跳 | 服务重启不漏文件、同名变化识别为新版本 |
| T05 通用任务内核 | T01/T02 | DB Job/租约、Outbox、DAG、退避、等待与取消 | 重复执行和租约过期不重复完成副作用 |
| T06 数据接入与映射 | T05 | HTTP事件、CSV导入、首院DB驱动、Schema与映射引擎 | 同timestamp分页、重复/坏行均可追溯 |
| T07 病理插件 | T04/T06 | 领域表、PIS/HIS Mock、关联、玻片齐套、报告版本、索引 | 多片/重扫/迟到/身份冲突不误提交 |
| T08 配置可视化 | T02/T05/T06 | 连接器表单、映射预览、流程画布、版本发布 | 无需改代码可创建并运行批准的流程 |
| T09 病理运维界面 | T04/T07 | 工作台、版本树、人工复核、文件/设备页 | 能回答每条记录为何未上报并执行正确修复 |
| T10 双模式交换 | T05/T07 | Mock API、交换库快照、HTTPS下载、逐项证据 | 同一包可独立投递两个目标而状态互不覆盖 |
| T11 PACS参考Profile | T10 | 16数据集字段差异、投影生成、冲突清单、采集器Mock | 经确认的样例字段/引用/下载路径一致；草案不默认生产 |
| T12 通用性样例 | T06/T08/T10 | CSV指标→HTTP Mock，独立Schema | 不修改病理无关核心模块即可运行 |
| T13 真实厂商接入 | T04＋厂家资料 | 设备Profile、完成检测、SDK/读取适配 | 06真机用例通过 |
| T14 真实医保接入 | T10/T11＋正式协议 | 鉴权、格式、回执、网络、对账 | 平台验收证据；无回执能力则如实记录确认方式 |
| T15 运维与发行 | T03—T12 | 离线安装、升级回滚、备份恢复、告警、手册 | 清洁环境安装和恢复演练通过 |

不要求串行等待全部任务才能看界面：T03/T04先给最小文件进度页面，T07再逐步丰富业务操作。开发排期需要根据人员、接口资料和真机窗口估算，本设计不承诺未经评估的固定周数。

## 4. 测试矩阵

| 编号 | 场景 | 必须断言 |
|---|---|---|
| A01 | 单个500MB以上及50GB合成文件 | 流式内存稳定；结果大小/hash一致 |
| A02 | 传片成功但ACK丢失 | 重传同片幂等，不重复累计进度 |
| A03 | 同一片索引传不同字节 | 409/422且旧已确认片不覆盖 |
| A04 | 服务进程在每个提交阶段被杀 | 按03恢复，无虚假成功或无主永久泄漏 |
| A05 | 低磁盘、多会话并发预留 | 超配阻断且保留安全空间，不写爆系统盘 |
| A06 | 同路径同名新文件、原地修改、复制中断 | 不沿用旧snapshot/hash或错误绑定扫描 |
| A07 | 主文件先到、伴随目录晚到 | Bundle未齐不得提交 |
| A08 | 路径穿越、重解析点、大小写碰撞 | 服务端与Agent均拒绝越界和冲突 |
| A09 | 凭据吊销、跨租户asset/session访问 | 拒绝且不泄露对象存在性/数据 |
| A10 | Range、HEAD、If-Range、无效范围 | 符合HTTP语义并且下载授权不绕过 |
| B01 | PIS先到/文件先到 | 都能最终关联，不丢输入 |
| B02 | 两医院/两来源/跨年同病理号 | 不串病例；来源域显式 |
| B03 | 一病理号3片，其中一片重扫 | 3张玻片、4次扫描，不显示4张玻片 |
| B04 | 预期3片，到2片＋一片重复 | 不判齐套 |
| B05 | 患者姓名相同但ID不同 | 不自动合并 |
| B06 | 原文条码、PIS、HIS冲突 | 隔离复核，原始证据保留 |
| B07 | 身份/机构/类别更正 | 新索引/包/提交版本，历史不可变 |
| B08 | 正式索引与草案字典混用 | Schema/Profile测试阻断；79/86示例正确 |
| C01 | 同一source事件重复10次 | Inbox/业务结果幂等，记录尝试可追溯 |
| C02 | 轮询同时间戳跨页＋补录＋删除 | 无漏数，窗口重读和盘点有效 |
| C03 | 旧租约Worker在超时后返回 | fencing阻止旧结果覆盖新状态 |
| C04 | 流程有环/端口不兼容/缺字典 | 发布前失败并定位节点 |
| C05 | 映射中出现代码执行/网络/无界正则 | 拒绝或限时，不执行任意代码 |
| C06 | 配置发布时旧任务仍运行 | 旧任务保持旧版本，新任务用新版本 |
| D01 | API超时但对方已受理 | UNKNOWN→查询，不能新建重复业务提交 |
| D02 | 重复/乱序/部分回执 | 逐项幂等；旧回执不回退新版本 |
| D03 | 文件未复制完成就准备发布 | 外部视图不可见 |
| D04 | 交换库已提交核心库未收到结果 | 按generation查证恢复，不重复发布 |
| D05 | 对方跨多次查询遇到新发布 | 按约定snapshot/父子重读处理；若无方案明确失败限制 |
| D06 | 对方完整下载但无业务回执 | 显示“已下载/待确认”，不显示医保成功 |
| D07 | 退款、作废、报告追加、补片 | 正确墓碑/更正，未过保留期不删文件 |
| D08 | Profile字段超长/未知格式 | 阻断，不截断或随意改扩展名 |
| E01 | 控制台查看原始敏感值 | 权限限制且审计 |
| E02 | 首次离线安装、服务自启、证书到期 | 有可执行手册与清晰失败提示 |
| E03 | 从备份恢复DB、文件、配置和密钥 | 关联与提交证据可用，孤立引用被检出 |
| E04 | 加入无患者的metrics业务 | 通用内核不改，流程和回执仍可运行 |

必须用真实授权WSI样本验证厂商格式。合成大文件只测试传输和存储，不证明病理图像可用。若转换为DICOM，另验文件头、金字塔、像素、方向、颜色及目标查看端，不只检验扩展名。

## 5. 性能与容量记录模板

记录工作站型号、扫描软件、磁盘、服务器CPU/内存/卷、网络、TLS配置、文件大小分布、并发、扫描是否同时运行、处理器版本。分别测源读、Agent hash、院内传输、服务器合并/hash、交换复制、目标读取。

验收报告给P50/P95耗时、峰值RSS、CPU/IO、重试恢复耗时和磁盘峰值，而非只给一个平均速度。存储容量按原件、重扫、派生、并发暂存、交换副本、备份和保留期估算，明确GB/GiB单位。

建议试点先覆盖持续运行一个完整业务周期及一次模拟长时间断网，再扩大设备数量。实际稳定性观察时长与医院约定，不把一次上传成功当生产验收。

## 6. 部署、升级与运行手册

服务器提供离线容器包或受支持系统服务包，包含依赖镜像、校验和、迁移、初始化、证书配置、healthcheck、备份/恢复、日志路径。Windows Agent提供签名安装程序或经医院批准的安装方式，配置服务账户、开机启动、故障重启、ACL、证书和卸载保留策略。

升级先备份配置/元数据，数据库采用expand-contract兼容迁移；任务和资产保持可恢复。回滚应用不能自动倒退外部平台提交，也不能盲目回滚数据库破坏新数据，需按迁移兼容矩阵处理。

上线监控至少包括：设备离线、最老未处理时间、源系统连接异常、磁盘预留不足、checksum失败、持续身份冲突、交换网关不可达、Profile拒绝、UNKNOWN增长、备份失败和证书即将到期。

## 7. AI开发工作方式建议

给实施AI的起始指令：先阅读00—07、检查契约样例，输出T01—T04实施清单并建立可运行闭环；所有未知外部接口采用显式Mock并登记阻断，不自行编造。每完成一任务，更新实现矩阵：已实现、自动测试通过、现场待验证、未实现。

每次交付包含代码改动、接口变更、数据库迁移、执行过的测试和未通过项；“页面完成”和“链路完成”分开。不要用固定假数据或始终返回success通过验收；UI看到的状态必须来自持久任务与证据。

## 8. 第一版可演示的完成定义

在两台测试机器或隔离环境中，扫描输出模拟器生成3张玻片及一次重扫；Agent自动采集，在上传中人为断网并恢复；服务器校验保存；导入PIS/HIS模拟记录并精确关联；UI正确显示缺片/齐套及版本；生成索引候选与冻结包；分别执行HTTP Mock提交和视图＋HTTPS供采集；模拟回执与无回执两种结果；随后追加报告，产生更正版本；最后从备份恢复并对账。再运行metrics CSV场景验证通用性。

达到上述结果可称“平台MVP闭环完成”；只有真实设备、真实PIS/HIS和正式平台分别通过现场验收，才可称“病理医保生产接入完成”。
