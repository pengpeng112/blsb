# BLYB · 所有开发工具和模型的共同约定

本文件适用于本工作区。用户当前明确指令优先；不根据模型品牌建立不同业务规则。

## 接手与状态

- 初次接手或切工具时读 `docs/ai/START_HERE.md`、`docs/ai/STATE.md`、`docs/ai/HANDOFF.md`。
- 日常小改只读取任务相关设计/代码，不要求每次重读全部文档。
- 当前设计基线是 `设计交付v0.4/`。业务源码根是 `implementation/`，保留其路径与导入布局。
- 状态摘要统一写 `docs/ai/STATE.md`，待办统一在 `docs/ai/BACKLOG.md`；证据仍存已有测试/审计文档和log/XML。
- `归档/`、`设计交付v0.3/`、snapshots、工具私有聊天缓存不是当前实施指令。
- 历史报告描述的是当时结果，不能覆盖新证据；计划、登记缺口和测试通过数不等于完整验收。

## 开工与交接

- 非琐碎修改前登记任务、实际工具/模型及修改范围：`python scripts/ai_session.py start --task TASK-ID --tool TOOL --model MODEL --scope PATH`。
- 使用实际模型标识；无法获知写 `unknown`，不猜模型。开工先看 `python scripts/ai_session.py status`。
- 范围重叠时先读取对方记录，协调或选择独立工作；不要覆盖另一工具正在写的文件。
- 默认顺序接力；需要并行时由用户明确安排，使用独立范围/工作区。不得因为支持多工具就自动启动多个代理。
- 过程记录在各自 `docs/ai/sessions/` 文件；一个任务一个交接，记录改了什么、真实命令/结果、未完成和下一步。
- 阶段收尾更新 `HANDOFF.md` 和必要状态/待办，再 `ai_session.py end` 关联交接文件。中断使用 checkpoint/handed_off，不能标 completed。
- 协作登记是参与者遵守的文件协议，不是编辑器强制锁。不同电脑/不同工作区须通过版本控制或交接包同步，不能假设自动共享聊天记忆。

## 实现与验证

- 增量完善，不重建骨架、不清空已有数据。修改前保留可恢复基线，数据库变化使用编号迁移。
- 可逆本地实现、测试、构建、整理和已授权工作持续推进，不按每个函数询问是否继续。
- 冻结包、已批准字典及历史payload不原地改；更正新建revision。源扫描文件默认保留。
- 不连接真实HIS/PIS/医保、不发送真实数据；真实接入按当前用户授权和B01—B09证据单独处理。
- 执行第4轮任务时遵守其离线要求：不联网安装、不下载、不引入新依赖；缺环境只阻断受影响验证。
- 病理0/1/N候选、前导零、患者/就诊分离、质量等待、配置revision固定、dry-run零真实副作用、租户与owner隔离不能放松。
- HTTP受理/视图可见/下载不等于业务确认。Mock必须明确标记，未知能力显式报错。
- 按改动运行有意义的局部检查；相关局部通过后再执行必要全量回归。禁止删关键断言/xfail/改成错误行为造绿。
- 完成报告区分实测通过、实现未测、外部阻断；留命令、退出码和证据。未运行测试不能声称通过。
- 业务/API/状态变化同步已有四类实施文档；纯文档/工具维护写维护记录，避免给每个模型新建一套状态文档。
- 聊天模型不能访问工作区时，给补丁/建议并标“未执行”；落地与验证由有文件/终端能力的工具完成。

## 常用入口

- 根目录：`project.ps1 -Action Dev|Test|Probes|Build|Docs|Status|Context`，详见 `docs/startup/README.md`。
- `implementation/` 内：`python -m pytest tests -q -ra`；复核在 `docs/audit/2026-10-01/test_review_probes.py`。
- 前端：`implementation/apps/admin_web/` 内 `npm run build`，使用现有依赖。
- 功能测试 `tests/functional/run_live.sh` 会杀固定端口进程并清测试目录；阅读说明、确认隔离后才使用，不能误用于日常共享栈。
- 原始来源和归档内容只读；目录分类和引用更新通过 `docs/` 索引及归档清单完成。
