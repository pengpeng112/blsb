## 2. 设计要点（与 revision-2 的映射）

- **R2（F04/F05）**：`ParentAcceptanceTracker` 命名空间键 `父表:父ID`；证据分层 session（FAILED_CURRENT 终局优先）→ 当日非 mock 回执（最新 False=阻断、True=受理）→ 外部显式放行 → sent.jsonl 历史（跨日复用）；mock 回执永不作 real 证据；`skipped_same` 登记 `ACCEPTED_HISTORICAL`（主表也登记）。`main`/单表/`run_reconcile`/重放共用同一 tracker 实例或同构自建。
- **R3（F06）**：`pending-wait.json` 只存表名/ID/父ID/源时间/原因（零患者隐私），`upsert` 即时原子落盘（写失败计 failed 不推水位）；常规增量扫描（real、无 since_override、非重放）**先**按 ID 定向重查待办（`fetch_rows_by_ids`，离线/打桩回退宽窗过滤），源端已删行移入 `wait_expired` 不死锁；`reconcile-<D>.json` 每表输出 `window_rows/repushed/recovered_wait/parent_wait/skipped_invalid/failed`，顶层 `total_parent_wait/total_skipped_invalid`，>0 写 `RECONCILE-PARENT-WAIT`/`RECONCILE-INVALID` 告警行。
- **R4（F07）**：manifest 校验先于一切执行分支（`reconcile+manifest` 组合立即拒绝）；schema：table 与 `--table` 严格一致（拒 all）、target 白名单、source_instance 一致性、expires_at 过期拒绝、max_count 1..5000、空/超量/重复 ID 拒绝；`manifest_id` 可选（缺省按核心字段派生稳定 auto id）；逐行 `expected_source_time`/`expected_digest` 与源视图核对（VERSION_DRIFT 拒发并非零退出，**不依赖 --since**）；缺失目标打印清单非零退出；`manifest-state-<id>.json` 持久进度——同清单二跑已 SUCCEEDED 项零 HTTP（force 只绕 sent 旧账，不绕完成账与父门禁）；无 `--apply` 100% 零副作用（dry-run 仅校验+源端干跑预览）。
- **R1（F01/F02/F03/F08）**：见修订包 README；SQLite 等价语义在专项单测 `TestV15Views` 验证（3 报告不膨胀、同日 2 就诊置空等待、科室码不进 operatorId、H/L 不产 10/12）。
- **取数**：`fetch_rows` 为惰性生成器（`arraysize=2000`+`fetchmany`），旧打桩返回 `list[dict]` 完全兼容；`fetch_rows_by_ids` 真实路径参数化 IN 每批 ≤500，无驱动/无凭据回退宽窗+ID 过滤（上限 5000）。
