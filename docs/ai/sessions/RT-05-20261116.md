## 1. 改了什么（U02～U09 按任务书）

### 后端（必要写语义修复——如实登记，非"只改前端"）
- **rollback**（app.py）：reason 必填 ≥5（无 body → 422）；AuditEvent new_ref=
  {reason, rolled_back_at, already_rolled_back} 同事务；幂等保留（不重设时间戳）。
- **restore**（app.py 新端点）：见 API 矩阵 §RT-05；CLOSURE_DRIFTED 新错误码
  （409，contracts ERROR_CODES）；字典批准/有效期复用发布链校验；幂等=同源同闭包
  最新未回退发布；test_report.restored_from/restored_reason；不自动启用调度/发送。
- **run 闭包一致性**（app.py create_workflow_run）：与 worker `_launch` 同语义
  （未回退 release 闭包 pin pack；否则最新 PUBLISHED；rolled_back_at 尊重）——
  修复 API 侧无视回退标记、不按 release 固定 pack 的不一致（W10 测试锁定回落）。
- **lifecycle 理由**（plugins/report_targets.upsert_target）：升级 PILOT/PRODUCTION
  必填 reason ≥5 进审计；闸门（sole_pusher/独立证据）不松动。
- **元数据端点**：GET /api/v1/plugins（manifest 元数据）；GET /api/v1/schedules/meta
  （真实 job_types=known_job_types(registry)+枚举）。

## 4. 与任务书的差异（如实登记；详见接口与设计差异.md RT-05 节）

1. restore=发布级承载（新发布指向历史不可变闭包）；逐 revision 状态回退保持本地待修
   （任务书 §6.4 预留项），未以按钮文案宣称超出该语义的"恢复"。
2. run 闭包 API/worker 一致性修复超出 U06 字面（restore 无它则无运行时意义）。
3. rollback 加 reason=破坏性契约变更；唯一旧调用方（W10 测试）已迁移。
4. Metrics 本地 CSV 解析=客户端导入前预览；服务端 preview 仍为权威。
5. **浏览器逐页点击/视觉验证未执行**（无浏览器、约束禁下载）——如实列未测；SSR+
   静态写契约覆盖见测试记录。交互级事件请求测试（点击→实际 HTTP body 断言）未做。
6. sfc_loader 的 import.meta.env define 与 SFC_CACHE_NS 为测试基建增强（业务代码零改）。
7. **迁移 022 PG 幂等缺陷修复**（RT-04 产物缺陷，本轮回归 PG 升级路径首次暴露：
   DuplicateTable uq_esr_key_src）：packages/core_db/migrate.py `_022` PG 分支加
   pg_constraint 存在性检查（登记范围外文件 packages/core_db/migrate.py——回归
   必达项修复；SQLite 分支原有 DDL 检查不受影响）。
8. **影子 tables/pusher 桩二次同步**：INF-V14-LIVE 会话在 RT-05 运行期间改生产
   pusher.py（parent_fk 父未受理拦截）与 tables.py（parent_fk 元数据+13 序全开），
   生产文件本轮零触碰（禁改比对 mismatch 0）；影子 tables.py 同步 parent_fk/13 序
   （禁改红线"仅更新影子"），parity 测试 `_Receipts` 桩补 parent_ids_from_sent
   （按夹具父表 ID 放行——等价性只比对报文形状）。
