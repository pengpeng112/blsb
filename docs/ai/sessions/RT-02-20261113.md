## 1. 改了什么（按任务书步骤）

### 步骤 1：4 处 target_scopes 越权封堵（403 优先于 404 防枚举）
- `plugins/domains/medins_emr/routes.py`：全部 **7 个**端点入口统一
  `p.require_target_scope("medins_emr_sd")`（`list_txns`/`txn_detail` 原本连
  principal 都没接变量，已改为接住并校验）。机器 token（kind!=user）、
  platform_admin、`["*"]` 经 `Principal.target_scopes_effective()` 语义不变。
- `apps/core_api/report_target_routes.py`：`PUT /{code}` 入口补
  `require_target_scope(code)`；`POST` 新建业务在 platform_admin 角色门之上
  加全局范围防御检查（当前 platform_admin 生效范围恒不受限，属纵深防御）。
- `apps/core_api/ops_routes.py`：新增模块级 `_require_scope_or_global(p, tc)`——
  系统级对象（target_code 空）要求全局范围、业务对象要求该业务授权。应用于：
  `POST/PUT /api/v1/alert-rules`（update 同时校验**原** target_code 与**新**
  target_code，防改挂他人业务）、`enable/disable/run-now/runs` 调度、
  `ack/resolve` 告警。
- `apps/core_api/app.py` 旧接口：`GET /api/v1/alerts` 受限账号按
  `target_code.in_(授权集)` 过滤（系统级不返回、空范围恒空）；旧
  `GET /api/v1/submissions` 列表按 `ReportTarget.destination_id` 绑定过滤、
  详情做归属校验（未授权 404 不泄露存在性）。机器 token/["*"] 行为不变
  （新测试 `test_old_alerts_machine_and_star_unchanged` 等锁死）。

### 步骤 2：运维审计 + 最后管理员并发锁
- `ops_routes.py` 6 类写操作补 `AuditEvent`（复用 `contracts.api.audit`，
  trace_id=ctx.request_id）：`alert.ack`、`alert.resolve`、
  `alert_rule.create/update`（前后快照：code/name/target_code/kind/severity/
  enabled/revision）、`notification_channel.create/update`（快照只含
  code/type/enabled，**config 不入审计**）。调度 4 类审计原在
  `scheduling/scheduler.py` 服务层，核对无缺（测试
  `test_audit_schedule_enable_already_present` 验证 schedule.upsert+enable）。
- `system_routes.py` 新增 `_assert_not_last_active_admin(db, tenant_id,
  excluding_subject_id)`：`AuthSubject` 按 `id` 升序 `with_for_update()` 锁定
  全租户 `kind=user, status=ACTIVE` 集合 → 内存过滤 platform_admin 且
  `ConsoleAccount.locked_until` 未过期 → 幸存数 <1 抛 `CONFLICT`。
  `update_roles`（移除 admin 时）与 `lock_user`（锁定活跃 admin 时）都走它；
  409 文案统一"不能移除或锁定最后一名活跃平台管理员"。
  SQLite 忽略 FOR UPDATE（方言不支持），PostgreSQL 行锁语义以"双 Session
  交错"确定性测试等价覆盖（见 §4 差异登记）。

## 4. 与任务书的差异（如实登记）

1. 警告清理范围超出任务书点名的 3 个文件（同类 Query.get 警告共 10 业务文件
   +4 测试文件）；datetime 适配器警告任务书未点名但 <600 验收必须处理。
2. `Session.get(M, None)` 与 `Query.get(None)` 行为等价（均返回 None）但前者
   发 SAWarning——4 个可空主键点补守卫，属语义保持的消警告措施。
3. 双管理员**真双线程**并发在 SQLite 测试库存在已知陈读窗口（SQLite 无
   FOR UPDATE、写锁串行但读不重验）——生产 PostgreSQL 行锁语义以"双 Session
   交错"确定性测试等价覆盖（s1 提交后 s2 必读已提交状态），不强测 SQLite
   不具备的保证。
4. `lock_user` 一并纳入最后管理员保护（任务书步骤 2 提及锁定场景；原实现
   完全无保护）。
5. `POST /api/v1/alert-rules` 的范围校验在 platform_admin-only 角色门之上
   属纵深防御（platform_admin 生效范围恒不受限，当前不可触发）。
