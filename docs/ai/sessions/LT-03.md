## 步骤 4 关键结论（任务书 CAUTION，写入交接的证据）

**药品真实发送不经过 `core_handlers.perform_push`**，闸门无法影响它：
- worker 药品发送 job：`apps/worker/engine.py` → `plugin.JOB_HANDLERS["drug_trace.send"]=_j_send` →
  `service.perform_send`（证据测试 `test_drug_trace_real_send_does_not_call_perform_push`
  以 `inspect.getsource` 断言 service 全文无 `perform_push` 引用）；
- `plugin.py` 中唯一 `perform_push` 字符串在 `_destination_adapter` 的 docstring（该适配器
  供病理/metrics 工作流与手动提交用，内部仍走 `perform_send`）；
- **附带发现并修复**：`Destination` 模型无 `plugin_id` 列，`perform_push` 旧代码
  `dest.plugin_id` 会 AttributeError（真目的地路径从不可用）——改为按
  `profile_revision` 前缀解析适配器键（药品=alihealth_yljg_*，generic=destination.*）。

**闸门范围**：仅 `profile_key.startswith("destination.")` 的真实 generic 目的地；
药品 profile 键不进闸门分支（沿用 DrugTraceProductionEvidence 门禁）。
**用户红线遵守**：码上放心/传染病现有链路零触碰（禁改清单 mtime 佐证）。

## 实现要点（复查入口）

- **游标 datetime 绑定修复**：decode_cursor 必须把 ts 解析为 datetime 再传 ORM——
  SQLite DateTime 列存空格分隔格式，与 ISO 'T' 字符串直接比较恒 False（分页失效），
  调试实录见测试 `test_cursor_pagination_no_dup_no_loss`。
- 新错误码注册：TARGET_REQUIRED(400)、USE_DOMAIN_WORKFLOW(400)（contracts.ERROR_CODES 追加）。
- BLYB_NET_TESTS 门（非 xfail）：send 网络测试默认跑（本机全过）；CI 可设 0 跳过。
