## 1. 数据层

| 差异 | 设计 | 实现 | 理由 |
|---|---|---|---|
| 核心库默认引擎 | PostgreSQL | SQLAlchemy 抽象：默认 SQLite(WAL) 本地开发/测试；`BLYB_DATABASE_URL` 指向 PostgreSQL 用于生产 | 本机无 PostgreSQL；迁移经 SQLAlchemy 可移植。**SQLite模式限制**：无 `FOR UPDATE SKIP LOCKED`（租约用 UPDATE 竞争+epoch fencing 等价实现）、JSON 为 JSON 文本、并发写吞吐低。生产必须 PostgreSQL |
| 时间存储 | 带时区UTC | UTC 朴素值（SQLite 不保时区），API 层 ISO 输出 | SQLite 兼容；语义一致 |
| 敏感证件号 | 加密或批准保护；密钥化摘要匹配 | API 全程脱敏（掩码）；冻结取值时经"受控来源"直读合成仓储；**明文未加密落库于 PatientReference.identity_snapshot 之外的路径不存在，但 identity_snapshot 含脱敏快照**；生产需接密钥服务 | 本地合成数据无真实患者；差异已列为上生产前整改项 |
| `size_bytes` 用 BIGINT | BIGINT | Integer（SQLite 无差异；PG 迁移时换 BigInteger） | 本地2GB内验证；PG迁移清单已列 |
| 新增支撑表 | — | `operation`（202异步操作落点）、`idempotency_record`、`auth_subject`（四类主体）、`external_blocker`、`alert_event` | 04 §4/§5 与 09 §3 的实现落点，04未列明细 |

## 2. API

| 差异 | 设计 | 实现 |
|---|---|---|
| OpenAPI | 草案仅覆盖关键链路，要求实施补全 | FastAPI 自动文档（/docs）随代码生成；04 §5 目录全部实现（除下述）；`POST /submissions`（直接创建）未实现单端点——提交由工作流 `deliver.push` 产生，`POST /submissions/{id}/corrections` 提供更正入口（D06测试断言 404/405 属预期） |

## 3. 工作流与节点

| 差异 | 设计 | 实现 |
|---|---|---|
| metrics 示例 DSL | `map → send` 直连 | 我们端口规则更严格：`deliver.push` 只接受 `validated`——副作用前必须显式验证节点（contract测试断言该差异并记录于此） |
| 画布 | 拖拽DAG | 首版：固定节点线性展示 + 后端DSL校验/发布/执行/回放（07 §7.5 允许"固定节点类型+线性/条件分支"）；拖拽编辑为后续 |
| `needs_review/invalid` 边 | 运行时转WAITING_HUMAN/INVALID | step 状态已支持 WAITING_HUMAN；`on:needs_review` 边类型在DSL校验接受，执行器当前按 WAITING_HUMAN 处理 |

## 5. 测量方法学（性能）

- starlette `TestClient` 会保留请求体导致内存测量失真——已定位；性能测试改用
  独立子进程真实uvicorn采样RSS（`tests/performance/_server_proc.py`）。
- httpx 客户端大对象循环引用不触发GC阈值：Agent 每16片 `gc.collect()`
  （工程缓解；上游行为已记录）。

## 6. 其他已知限制（不构成设计违背）

1. `quality reevaluate` 仅支持 acquisition/pathology_case 两类实体（其他实体返回 CAPABILITY_UNSUPPORTED）。
2. 自动墓碑：`tombstone` 表与写入路径已备，自动触发等 B07 删除语义确认。
3. PACS `jinan-imaging-v2-draft` 仅实现 pathology 投影子集（chk_info/asset_info）；
   16数据集全量投影与字段冲突清单未实现（Profile未确认，按 ADR-08 不预造）。
4. 回执轮询 `destination.poll_receipts` 指数退避（1s→2s→…封顶60s，poll_count 入 payload）；
   重排以 `{submission_id}#poll{N}` 代次dedup开新作业行（复用原键会被去重提前返回、
   且原作业被 finish_job 置 SUCCEEDED 导致链条中断——深度核查H-09发现并修复）。
   每轮重排留一行 SUCCEEDED 作业（60s封顶下≤1440行/天/提交），上生产前可加清理。
5. 审计 `audit_event` 未做分区/归档（量小）；上生产前按04 §8 分区。
6. 通用未捕获异常500响应包含trace尾部——生产需关闭（整改项）。
7. Agent 目录模式（无vendor manifest）：稳定窗口仅产生候选+人工放行（03 §3.1 模式3），
   已实现候选枚举 API（`discover_directory_candidates`），未接UI按钮。
8. 连接器页"覆盖能力"列对 HIS 连接器也显示 PIS 流口径（`_coverage` 固定返回 pis.created/
   pis.cases.partition_scan，未按插件区分）——展示层限制，待 HIS 覆盖语义确认后细分。
9. 视图发布列表"行数"取核心库 PublicationItem 行数；演示发布路径未写 PublicationItem
   （交换库投影行正常，D06 断言不受影响）→ UI 显示0。发布器补写条目行为后续项。
