# 网络开通与其余资料协调单

对应[执行计划](README.md)，状态以2026-10-20已有实测为起点；不是本计划阶段新增测试结果。
**目标是把软件和部署材料一轮补齐；只有下面非网络输入也落实，才能称“最后主要等网络”。**
既有EXT-01—12继续作为外部事项编号，本表为本期具体化，不新增同名编号、不把所有EXT自动关闭。

## 1. 可直接提交的网络申请

业务源端口均由系统分配，申请填写“任意/临时端口”，下表列的是目的端口。

| 用途 | 源地址 | 目的地址 | 协议/目的端口 | 级别与当前证据 |
|---|---|---|---|---|
| 读取HIS两视图 | <prod-host> | <his-host> | TCP 1521 | 主用；10-16曾两次TCP成功，<prod-host>实际数据库认证/受限权限仍须验证 |
| 调用DMZ专用转发 | <prod-host> | <relay-net-host> | TCP 443 | 主用；10-20连接拒绝且DMZ无监听，必须先部署再验网络 |
| 转发备用入口 | <prod-host> | <relay-net-host> | TCP 8443 | 备用；默认不监听、不计主链路验收，只有明确启用并验收后使用 |
| 调官方平台 | <relay-net-host> | eco.taobao.com | TCP 443 | 主用；10-20直连超时，需核查出口/NAT/域名策略/回包；不固定单个解析IP |
| 院内DNS | <prod-host>、<relay-net-host> | 院内批准DNS服务器，地址待网络科填 | UDP 53＋TCP 53 | 使用域名时必需；服务器/容器实际解析路径分别核查 |
| 院内校时 | <prod-host>、<relay-net-host> | 院内批准NTP服务器，地址待填 | UDP 123 | 两机分别验证；不擅自使用公共NTP或大幅跳时 |
| 管理<jump-host>跳板 | 已批准运维终端，实际源IP核实 | <frontend-host>4 | TCP <ssh-port> | 既有管理路径；与上报业务端口分开 |
| 跳板管理<prod-host> | <frontend-host>4 | <prod-host> | TCP 22 | 已有普通二次SSH成功；不要求开启被禁用的TCP forwarding |
| 管理DMZ | 已批准运维终端/堡垒机，实际源IP核实 | <relay-net-host> | TCP 22 | 已有开发终端登录成功；不假定<jump-host>→DMZ22也通 |
| 使用管理页面 | 医院批准管理终端网段，待填 | <prod-host> | TCP 443 | 浏览器同源入口；与<prod-host>主动访问DMZ443是不同方向 |

不申请<prod-host>公网直连，不开放后端8000/8001/8002或PG5432宿主端口。
DMZ既有8001维持原用途，不能作为未核实的本项目接口。
DMZ主动访问<prod-host>:22/443不是上报链路前提；仅在院方明确选择该运维方向时单独申请。
有状态防火墙放行已有连接回包通常无需申请反向新连接；无状态ACL则由网络科配置相应返回规则，不能只写“双向全部放开”。

过去实测通的是DMZ→gw.api.taobao.com:80，当前正式方案使用eco.taobao.com:443；80不作为HTTPS验收替代。
10-20当次官方目标59.82.121.55仅为取证地址，CDN解析变化不能仅维护这一个IP。

```text
工单号/负责人/实施时间：

DMZ→eco.taobao.com443：出口/NAT地址、域名规则、TLS/SNI检查要求：
是否必须走院方出网代理：否 / 是；若是，代理地址端口/认证受控引用：
院内DNS地址（至少主/备）：
院内NTP地址/允许来源：
管理终端/堡垒机实际源IP及SSH路径：
DNS/443策略命中日志时间及允许/拒绝原因：
网络改动回退与联系人：
```

判断顺序：先本机监听/服务身份→本机可信TLS/mTLS→真实源TCP→跨机TLS/mTLS→官方DNS/TCP/TLS→签名只读查询。
只看到拒绝不能断言防火墙未放通；只有TCP成功不能断言TLS/API成功；安装脚本exit0不能代替网络实测。
