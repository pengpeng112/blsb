## 0. 为什么做

院方说明（`数据上报/2、医保电子病历上报/说明.txt`）原文："**该接口不用开发，只要确保能够调试通发送成功即可**"。
所以这块的正确产品形态不是"再做一个自动上报插件"，而是：
1. 把 V2.0 规范和测试报文**结构化成契约**（交易清单、字段、必填、长度、字典），存成平台 Profile；
2. 做一个**联调工具台**：选交易号 → 载入合成样例 → 编辑 → 本地校验 → 生成签名/报文头（规则待确认的部分明确标注）→ 发 Mock 或导出"可在院内手工执行的请求" → 记录每次联调结果。
这同时给 `implementation/profiles/`（目前为空目录）一个明确用途：**存放各上报平台的契约 Profile**，后续影像云、病理云沿用同一格式。

> [!CAUTION]
> `数据上报/2、医保电子病历上报/` 下的测试报文与 `11401入参.txt` **可能含真实姓名/证件号**（如样例中的 opter_name、certno）。
> **禁止把这些文件内容复制进代码库、测试夹具、文档或聊天**。只允许程序读取它们来**提取字段名/结构/类型**；样例值一律用合成值重新生成。
> `调用地址.txt` 不得抄录到任何新文件；真实地址只能由用户在运行时配置。

### 步骤 2：Profile 格式（`profiles/README.md`）

```text
profiles/<target_code>/
  profile.json        {"target_code","name","spec_version","spec_source":[{"path","sha256"}],"extracted_at","extractor_version","status":"DRAFT|REVIEWED"}
  transactions.json   [{"code":"11101","name":"...","direction":"upload|query","fields_ref":"fields/11101.json","sample_ref":"samples/11101.json","notes":""}]
  fields/<code>.json  {"code","envelope_ref":"fields/_envelope.json","root":"input","nodes":[
                         {"path":"input.patn_bas_info","type":"object|array","required":true,"children":[
                           {"path":"input.patn_bas_info.certno","name":"证件号码","type":"string","max_len":50,"required":true,"dict":null,"format":null,"sensitive":true}
                         ]}]}
  dicts/<dict>.json   {"code","name","values":{"01":"居民身份证",...}}
  samples/<code>.json 合成样例（所有值为合成）
  EXTRACTION_REPORT.md
```
`sensitive: true` 标记证件号、姓名、电话、地址等字段——联调记录与日志对这些字段**一律打码**。
Profile 是**派生物**：原件 sha256 记录在 profile.json；原件更新 → 重新生成新目录或递增 spec_version，旧的不改（遵守"冻结不原地改"）。

### 步骤 3：提取工具

- `docx_tables.py`：输出 `[{"heading_path":["4 接口说明","4.1 ..."],"rows":[[...],...]}]`。表格与最近的上级标题关联，用于识别"这张表属于哪个交易"。
- 识别规则：标题中含 5 位数字交易号（正则 `\b1\d{4}\b`）→ 该标题下的参数表归属该交易；表头包含"参数代码/字段名"类列 → 参数表。无法自动归属的表列入 EXTRACTION_REPORT"人工待核"。
- `sample_shape.py`：读样例 JSON（注意文件可能是 GBK 编码：先试 utf-8，失败试 gbk，**两者都失败记录并跳过**），输出字段路径树、类型、数组标记，**丢弃所有值**。
- `build_profile.py`：以 docx 字段表为主、样例结构为辅合并；样例有而规范无的字段标 `"source":"sample_only"`；规范有而样例无的标 `"source":"spec_only"`。生成合成样例：string→按字段名生成"测试"值（证件号用 `000000199001010000`，姓名用"测试患者"，日期用 `2026-01-01 00:00:00`，代码字段仅从已提取的明确字典生成合成示例并标示，不把首值当业务默认值），数值→0，数组→1 个元素。
- 命令：`python -m tools.spec_extract.build_profile --target medins_emr_sd --spec "<docx路径>" --samples "<样例目录1>" --samples "<样例目录2>" --out profiles/medins_emr_sd`（按实际包结构调整调用方式）。
- **提取覆盖率**写进报告：规范交易数、成功提取字段表的交易数、样例覆盖的交易数、三者差集。

### 步骤 4：契约校验器

```python
def validate_message(message: dict, fields_contract: dict, envelope_contract: dict | None, dicts: dict) -> list[dict]:
    # 返回 [{"path":"input.patn_bas_info.certno","code":"REQUIRED|TYPE|MAX_LEN|DICT|FORMAT|UNKNOWN_FIELD","message":"中文说明"}]
```
- 未知字段默认 WARN 级（`"level":"warn"`），其余 error。
- 日期格式按字段 `format`（如 `yyyy-MM-dd HH:mm:ss`）做格式及真实日历语义校验；正则不能接受不存在的日期。
- 长度按**字符数**还是**字节数**：看规范说明；未说明标LENGTH_UNIT_UNCONFIRMED；可演示字符长度，但不能宣称正式长度校验已通过。
- 单测：每种错误码至少 2 例；嵌套数组路径如 `input.diseinfo[0].diag_code`。

### 步骤 5：报文封装与签名器（`plugins/destinations/medins_gateway/`）

- `envelope.py::build_envelope(config, info_code, input_body, now) -> dict`：字段来自 `config`（fixmedins_code、mdtrtarea_admvs、insuplc_admdvs、opter、opter_name、opter_type、recer_sys_code、infver、dev_no 等），**不从样例读值**。
- `msgid.py`：若规范明确给出msgid规则并有章节证据，按规范实现；否则返回MSGID_RULE_UNCONFIRMED；Mock可用明显TEST前缀临时标识，不能冒充正式规则。只对规范已证实的规则测试长度/唯一性。
- `signers.py`：`class Signer(Protocol): def headers(self, body_bytes, now) -> dict`；NoneSigner仅供明确无签名的Mock；正式算法缺失时返回SIGNATURE_UNCONFIRMED，不实现猜测的TifHmacSigner。规范有明确算法与SDK向量后另行实现验证。
- `client.py`：urllib POST JSON，目标白名单来自配置，超时 30s，返回原始状态码+解析后的 `infcode/err_msg`（字段名以规范为准），响应体落库前对 sensitive 字段打码。
- **真实地址发送**：服务端独立MOCK_ONLY能力及loopback目标校验，不依赖可编辑的Target生命周期；篡改is_mock/lifecycle/runtime_kind也必须拒绝真实发送。
