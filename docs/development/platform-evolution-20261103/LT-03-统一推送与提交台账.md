## 0. 为什么做

现在每接一个上报平台就要自己写发送、重试、回执解析：药品追溯有私有 `alihealth_drugtrace`，传染病在平台外用 urllib 自己发，
通用层只有 Mock。v0.4 ADR-01 要求"Connector 管协议、Profile 管数据集"，所以要：
①定义统一的目的地适配器协议；②做一个**配置驱动的通用 HTTP JSON 适配器**——大多数国内上报平台（传染病前置机、各类前置机/HTTP 接口）
只需配置 URL、成功判定、可重试码就能接；③做一个**统一提交台账**，解决"先 limit 后筛选漏异常"的历史 bug，
并给 UNKNOWN 一条受控的人工处置路径。

## 1. 交付物

1. `packages/connector_sdk/destination.py`：`DestinationAdapter` 协议 + `SendResult`/`QueryResult` 数据类 + `ReceiptRule` 声明式回执规则。

3. Mock 服务扩展：`plugins/destinations/mock_http/server.py` 增加 `inf_frontend` 行为档（模拟传染病前置机 errorCode 语义）。
4. 适配器注册：通过 `core_handlers.register_destination_adapter` 接入 `perform_push`；**真实目的地必须先过 LT-01 的 `assert_target_can_send_real`**。
5. 统一台账 API：`GET /api/v1/report-center/submissions`（必须带 target，SQL 先筛后限、游标分页）+ 详情 + 人工处置。
6. 药品追溯台账钩子 `hook.ledger_search`（只读，复用药品已有查询；若药品已有先筛后限的查询函数就直接包一层）。
7. 测试 ≥30 个；全量回归不新增失败。

### 步骤 2：协议定义 `packages/connector_sdk/destination.py`

```python
from dataclasses import dataclass, field
from typing import Protocol, Any

OUTCOMES = ("ACCEPTED", "CONFIRMED", "PARTIAL", "REJECTED", "RETRYABLE", "UNKNOWN", "UNSUPPORTED")

@dataclass
class SendResult:
    outcome: str                      # ∈ OUTCOMES
    http_status: int | None = None
    remote_ref: str | None = None     # 对方流水号（有则填）
    error_code: str | None = None     # 对方业务码，如 "02"
    error_message: str = ""           # 已脱敏、≤500 字
    retry_after_seconds: int | None = None
    attempts: int = 1
    raw_digest: str = ""              # 响应体 sha256 前 16 位（不存原文）

@dataclass
class QueryResult:
    outcome: str
    remote_ref: str | None = None
    error_code: str | None = None
    error_message: str = ""

@dataclass
class ReceiptRule:
    """声明式回执判定。按顺序匹配，命中即返回 outcome。"""
    json_path: str                    # 简单点路径，如 "result" / "data.code"
    op: str                           # eq | in | exists | not_exists
    value: Any = None
    outcome: str = "ACCEPTED"

class DestinationAdapter(Protocol):
    plugin_id: str
    def capabilities(self) -> set[str]: ...          # {"send","query","void"} 子集
    def validate_config(self, config: dict) -> list[str]: ...   # 返回错误列表，空=合法
    def send(self, config: dict, payload: dict, idempotency_key: str) -> SendResult: ...
    def query(self, config: dict, remote_ref: str) -> QueryResult: ...   # 不支持→raise CapabilityError("CAPABILITY_UNSUPPORTED")
```

`json_path` 解析自己写（只支持 `a.b.c` 与 `a.0.b` 下标），写单测。

### 步骤 3：通用 HTTP JSON 适配器 `plugins/destinations/generic_http_json/`

文件：`__init__.py`、`adapter.py`、`config_schema.py`、`redact.py`、`rate.py`、`README.md`。

**配置结构**（存于 `Destination` 的配置列；先看模型实际列名，若是 `config` JSON 就放这里）：

```json
{
  "base_url": "http://127.0.0.1:8090",
  "allowed_hosts": ["127.0.0.1"],
  "allowed_ports": [8090],
  "allowed_schemes": ["http", "https"],
  "method": "POST",
  "path_template": "/api/{business_type}",
  "headers": {"Content-Type": "application/json"},
  "credential_ref": null,
  "timeout_seconds": 15,
  "max_attempts": 3,
  "backoff_seconds": [2, 4, 6],
  "rate_limit_per_minute": 60,
  "receipt_rules": [
    {"json_path": "result", "op": "eq", "value": true, "outcome": "ACCEPTED"},
    {"json_path": "errorCode", "op": "in", "value": ["01", "99"], "outcome": "RETRYABLE"},
    {"json_path": "errorCode", "op": "exists", "outcome": "REJECTED"}
  ],
  "default_outcome": "UNKNOWN",
  "error_code_path": "errorCode",
  "error_message_path": "desc",
  "remote_ref_path": null
}
```

规则：
- `validate_config`：base_url 的 scheme/host/port 必须在 allowed_* 中；`path_template` 只能用 payload 顶层字段占位且值只允许 `[A-Za-z0-9_-]`；timeout 1—120；max_attempts 1—5；receipt_rules 的 outcome 合法。错误返回中文说明列表。
- **每次 send 前再校验一次最终 URL 在白名单**（防 path_template 注入）——照 `pusher.check_url` 的思路。
- `credential_ref`：只允许形如 `env:VAR_NAME`；运行时 `os.environ[VAR_NAME]` 取值放入 `Authorization` 头；变量不存在 → 返回 `SendResult(outcome="UNSUPPORTED", error_message="凭据未配置: VAR_NAME")`，**不抛出明文**。
- 重试：outcome=RETRYABLE 或网络异常时按 backoff 重试；`time.sleep` 通过可注入的 `sleeper` 参数实现，测试里注入假的 sleeper。耗尽后：最后一次是 RETRYABLE（对方明确说服务端异常）→ 返回 `REJECTED`？**不**——返回 `UNKNOWN`（服务端异常不代表未入库），error_code 保留。网络异常耗尽同样 `UNKNOWN`。
- 非 2xx HTTP：4xx（除 408/429）→ REJECTED；408/429/5xx → RETRYABLE（429 读 `Retry-After` 头填 retry_after_seconds）。
- 响应非 JSON → UNKNOWN，error_message="响应不是 JSON"。
- `rate.py`：进程内令牌桶（每个 destination_id 一个桶）；超出时 sleep 到可用（同样用可注入 sleeper）。在 README 写明"跨进程限速未实现，单 worker 部署下有效；多 worker 需 LT-04 后续增强"。
- `redact.py`：`redact_text(s)`：①连续 ≥6 位数字替换为 `***`（证件号、电话、病案号）；②18 位身份证模式替换；③中文姓名无法可靠识别，**所以 error_message 只保留前 200 字**；单测覆盖。
- 适配器对外暴露两个入口：
  - 类 `GenericHttpJsonAdapter`（实现协议）；
  - 函数 `perform_generic_push(db, tenant_id, submission, payload) -> dict`：读 Destination 配置 → 调 send → 写 `DeliveryAttempt`（每次尝试一行，attempt_no 递增，`request_digest`、`http_status`、`outcome`、`response_snapshot={"error_code","error_message","remote_ref","raw_digest"}`）→ 按 outcome 更新 `submission.state`（ACCEPTED/CONFIRMED/PARTIAL/REJECTED/UNKNOWN；UNSUPPORTED→REJECTED 并在 snapshot 注明）→ commit → 返回与 `perform_push` 现有返回同形状的 dict。

在 `app_runtime.load_registry` 中（基线处理器旁）调用
`register_destination_adapter("destination.generic_http_json", perform_generic_push)`，并加
`("deliver.push","destination.generic_http_json"): h_deliver_push` 处理器条目。

### 步骤 6：统一台账 `plugins/report_ledger.py` + 钩子

`domain_hooks.py` 追加：

```python
HOOK_LEDGER_SEARCH = "hook.ledger_search"
# fn(db, tenant_id, target_code, filters: LedgerFilter, cursor: str|None, limit: int) -> LedgerPage | None
@dataclass
class LedgerFilter:
    bucket: str | None = None         # REPORT_BUCKETS 之一
    date_from: str | None = None      # 'YYYY-MM-DD'（院内日期，UTC+8）
    date_to: str | None = None
    q: str | None = None              # 业务单号/提交ID 精确或前缀
@dataclass
class LedgerRow:
    id: str; target_code: str; business_key: str; bucket: str; raw_state: str
    created_at: str; updated_at: str; attempts: int; last_error_code: str | None; last_error_message: str
    detail_route: str | None = None   # 前端可跳的专页，如 "/drugtrace?bill=xxx"
@dataclass
class LedgerPage:
    items: list[LedgerRow]; next_cursor: str | None; total_estimate: int | None
```

**先筛后限硬规则**：所有过滤条件必须写进 SQL WHERE，再 `ORDER BY updated_at DESC, id DESC LIMIT :limit+1`；
游标 = base64(`updated_at|id`)，下一页条件 `(updated_at, id) < (cursor_ts, cursor_id)`（SQLite 与 PG 都支持元组比较？**不确定就写成 `updated_at < :ts OR (updated_at = :ts AND id < :id)`**）。
`limit` 1—200，默认 50。

- 通用实现（病理/通用 Submission）：按 `Submission.destination_id ∈ target 关联的 destination` 查；bucket 通过 `SUBMISSION_STATE_TO_BUCKET` 反查出状态集合放入 WHERE `state IN (...)`。
- 药品实现：在 drug_trace 已有的 outcomes/bill 查询函数里找是否有"先筛后限"的版本；**没有就新写一个只读查询**（对药品自己的表 SELECT），不改原函数。药品状态→桶用 LT-01 的 `DRUG_TRACE_STATE_TO_BUCKET` 反查。`detail_route` 填 `/drugtrace`。

**回归测试（重点）**：造 300 条记录，其中 5 条 UNKNOWN 且 updated_at 最旧；`bucket=UNKNOWN&limit=50` 必须返回这 5 条。这就是 2026-10-26 发现的 bug 的反例测试。
