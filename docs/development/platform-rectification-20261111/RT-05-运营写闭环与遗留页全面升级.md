## 0. 背景与目标

用户明确要求“**成为一个较为丰富、标准能够兼容多个上报要求的系统，且界面也需要完善下**”。
独立前端审计发现目前界面仍存在两大块明显短板：
1. **新运营页面的“管理写操作”偷工减料（后端 API 已写好，前端却只读没接按钮）**：
   - `Targets.vue` & `TargetDetail.vue`：没有“新建上报业务”抽屉，详情页的“配置”Tab 纯只读，后端早已写好的 `POST /api/v1/report-targets` 与 `PUT /api/v1/report-targets/{code}` 在前端调用次数为 0！
   - `Schedules.vue`：没有新建/编辑定时任务表单，也没有独立的调度详情运行统计视图，`POST/PUT /api/v1/schedules` 前端未接！
   - `Alerts.vue`：只有编辑已有规则，没有“新建告警规则”入口；“通知通道”Tab 纯只读，不能新建或修改本地文件/邮件/Webhook 通道配置（`POST/PUT /api/v1/notification-channels` 前端未接）！
2. **原 19 个页面中有 10 个核心业务/配置页完全未升级（仍停留在早期粗糙原型）**：
   - `Mapping.vue`（字段映射）：3 个裸 `<textarea>` 让人手敲 JSON 数组；
   - `Connectors.vue`（连接器）：下拉框写死 2 个名字，测试结果 `<pre>{{ JSON.stringify }}</pre>` 裸打，无抽样预览；
   - `Pack.vue`（医院配置包与发布）：整屏 `<pre>` 裸打 JSON，发布无前后版本对比（Diff）、无回滚按钮（后端已有 `/api/v1/config-releases/{id}/rollback` 接口，前端没做按钮！），还有重复表达式 `p.content.pack_key || p.content.pack_key`；
   - `Workflows.vue`（流程编排）：第 177 行 `catch` 把用户写错的非法 JSON **静默吞成 `{}` 空对象提交给后端**！节点拓扑无可视化流程图展示；
   - `Cases.vue`（病理工作台）、`Quality.vue`（质量队列，操作反馈 `msg` 赋值了却没写在模板里！）、`Review.vue`（关联复核，要手填 UUID 采集事件 ID）、`Lineage.vue`（字段血缘）、`Publications.vue`（视图发布，漏做后端已有的 `/revoke` 撤回按钮！）、`Metrics.vue`（指标导入）：全部缺乏统一 `<PageHeader>`、`<LoadingBlock>`、`<ErrorState>`、`<EmptyState>`、`<StatusTag>`、`<TimeText>` 与 `<JsonViewer>`！

本任务目标：**把全站剩余的所有半截子管理写操作和全部 10 个老页面一次性全面现代化升级**，消灭手敲裸 JSON 和裸 `<pre>`，打造真正专业、统一、好用的医院多上报管理工作台！

## 2. 详细实施步骤

### 步骤 1：补齐新运营中心的 4 处管理写操作闭环

1. **上报业务新建与配置编辑（`Targets.vue` & `TargetDetail.vue`）**：
   - `Targets.vue`（当用户含 `platform_admin` 角色时）：右上角 `<PageHeader #actions>` 提供“新建上报业务”按钮 → 打开 `<Drawer>` 表单（编码、名称、分类下拉、主管单位、插件 key 下拉、模式 PUSH/PULL/HYBRID、运行形态 PLATFORM/EXTERNAL/MANUAL、负责科室、说明文档路径），提交 `POST /api/v1/report-targets`。
   - `TargetDetail.vue`“配置”页签（`platform_admin` 或 `config_editor` 可见）：提供“编辑业务配置”按钮 → 打开 `<Drawer>` 编辑生命周期、运行形态、唯一推送方状态与备注、负责科室、联系人、频率说明、README 路径（带乐观锁 `revision`，遇到 409 用 `toast.error` 提示“配置已被他人更新，已为您刷新最新数据”）；当将生命周期改为 `PILOT` 或 `PRODUCTION` 时弹出 `<ConfirmDialog require-reason>` 要求填写 ≥5 字审批理由。
2. **调度任务新建与编辑（`Schedules.vue`）**：
   - `platform_admin` 可见“新建定时任务”与行内“编辑”按钮（注：`observe_only` 镜像调度禁止编辑执行参数，保持只读观测标签）。
   - `<Drawer>` 表单包含：任务编码、名称、关联上报业务下拉、Job 类型下拉（从后端返回或已知注册列表选择，不手盲敲）、Cron 表达式输入框（输入防抖实时调 `/api/v1/schedules/preview` 在下方展示“未来 5 次院内触发时间”，表达式非法时红字提示后端中文原因）、错过策略（`SKIP` / `RUN_ONCE`）、并发策略（`FORBID` / `ALLOW`）、最大运行时长（秒）、维护避让窗口列表增删器（开始 `HH:mm` ～ 结束 `HH:mm`，无需手写 JSON！）、载荷模板编辑器（带 JSON 语法实时校验）。
3. **告警规则新建与通知通道管理（`Alerts.vue`）**：
   - “告警规则”页签增加“新建告警规则”按钮（复用已有的 9 种 `kind` 动态参数表单 `RULE_FORMS`，选择级别、冷却分钟、关联业务、勾选通知通道），调用 `POST /api/v1/alert-rules`。
   - “通知通道”页签（`platform_admin` 可见）增加“新建通道”与行内“编辑”按钮：按 `type`（`file` / `smtp` / `webhook`）动态切换表单字段；对 `smtp` 和 `webhook` 清晰展示琥珀色安全横幅“密码与 Webhook 地址仅填写服务器环境变量名（如 `INF_WATCHDOG_WEBHOOK_URL`），且本批服务端外发策略默认停用，启用须经运维授权”；提供本地 `file` 通道的“测试写入”按钮调用 `/test` 接口并 `toast` 反馈结果。

### 步骤 2：可视化升级三大平台配置核心页（`Mapping` / `Pack` / `Connectors` & `Workflows`）

1. **字段映射可视化规则构建器（`Mapping.vue`）**：
   - 告别裸敲 JSON！升级为**双模式（可视化表格构建器 ⇄ 高级 JSON 视图互转）**：
   - 左/上区选择或新建映射集（`mapping_key`、目标 Schema），主体为**可视化映射规则表**：每一行可通过下拉框和输入框配置 `目标字段路径`、`转换算子 op`（下拉选择 `mapping_engine` 支持的白名单算子：`field` 取源字段、`const` 常量、`dict_map` 字典映射、`concat` 拼接、`date_format` 日期格式化、`coalesce` 兜底等）、`源字段 / 参数`、`引用字典下拉`（自动拉取 `/api/v1/dictionaries` 列表供点选！），支持增删行与上下移动顺序！
   - 右/下区“模拟试算面板”：点击“一键填入示例源记录”或编辑测试输入 → 点击“执行映射模拟” → 左右并排用 `<JsonViewer>` 对比“输入源数据”与“映射输出报文”及逐字段命中情况！
2. **医院配置包与版本发布 Diff + 回滚台（`Pack.vue`）**：
   - 修复 `p.content.pack_key || p.content.pack_key` 低级笔误，全部裸 `<pre>` 替换为结构化描述卡片 + `<JsonViewer>` + 字典明细表（支持新建/查看字典条目键值表）。
   - 新增组件 `src/components/DiffViewer.vue`（约 80 行纯 TS/Vue 键值行级差异对比组件）：在发布新 `ConfigRelease` 前或点击历史发布记录时，高亮显示与上一版本相比**新增（绿）、修改（黄）、删除（红）**的配置项与 digest 变化！
   - 为历史发布版本补齐**“回滚到此版本”**按钮（调用后端已有的 `POST /api/v1/config-releases/{release_id}/rollback`，带 `<ConfirmDialog require-reason>` 必填回滚理由）！
3. **流程编排防呆与 SVG 拓扑预览（`Workflows.vue`）**：
   - **修致命防呆 Bug**：彻底删除第 177 行附近 `try { JSON.parse(...) } catch { return {} }` 静默吞错代码！当节点配置 JSON 语法有误时，输入框标红并用 `toast.error` 明确指出哪一个节点的 JSON 解析失败，阻止提交脏数据！
   - 新增轻量纯 SVG 有向流程图组件 `src/components/DagGraph.vue`：根据当前工作流的 `nodes` 和 `edges` 自动按拓扑层级排列绘制节点框与箭头连线；在下方“运行记录”点开某次 `WorkflowRun` 时，节点框按该次运行的各 Step 状态（`SUCCEEDED` 绿 / `RUNNING` 蓝 / `WAITING` 黄 / `FAILED` 红）实时染色，直观看到卡在哪一步！
4. **连接器管理升级（`Connectors.vue`）**：
   - 插件类型改为完整枚举说明卡片（PIS Pitaya SQL Server、HIS 病案 Oracle、药品追溯视图、HTTP 事件源、本地目录源等），配置表单按所选连接器类型给出结构化字段输入（同时保留高级 JSON 折叠区），连通性测试与盘点覆盖（`coverage`）结果用 `<StatusTag>` + 统计表 + `<JsonViewer>` 清晰呈现。

### 步骤 3：全面升级其余 6 个业务与治理页面（`Cases` / `Quality` / `Review` / `Lineage` / `Publications` / `Metrics`）

统一使用 `<PageHeader>`（Mock 页面醒目挂 `:mock="true"` 紫色徽标）、`<FilterBar>`、`<DataTable>`、`<StatusTag>`、`<TimeText>`、`<BytesText>`、`<Drawer>`、`<ConfirmDialog>`、`<EmptyState>`、`<ErrorState @retry>`、`<LoadingBlock>` 重构：
1. **`Cases.vue`（病理工作台）**：左侧/主表支持按状态筛选病例列表（分列清晰展示患者关联、就诊关联、临床就绪状态徽标）；点击病例打开右侧宽 `<Drawer>` 分栏展示：病例与脱敏就诊信息、玻片与扫描有效版本树、关联的质量问题与“为什么未上报”诊断提示。
2. **`Quality.vue`（质量队列）**：修复原页面 `msg` 赋值却未渲染的死代码（改用 `toast.success/error`），按规则码（`QF-*` 附中文解释）与状态筛选，单条/批量重新评估带 loading 态。
3. **`Review.vue`（关联复核）**：**不再让用户盲填采集事件 UUID！** 页面挂载自动拉取 `GET /api/v1/acquisitions` 待复核/未绑定采集列表供直接点选（仍支持搜索过滤），选中后一键加载条码候选卡片（清晰展示 0/1/N 候选、文件名、PIS 匹配信息），通过 `<ConfirmDialog require-reason>` 填写复核理由完成绑定。
4. **`Publications.vue`（视图发布 PULL）**：补齐原页面漏掉的**“撤回发布”按钮**（调用后端已有的 `POST /api/v1/publications/{publication_id}/revoke`，必填撤回理由，已撤回行显示撤回时间 `<TimeText>`），证据详情用 `<Drawer>` + `<JsonViewer>` 展示。
5. **`Lineage.vue`（字段血缘）** 与 **`Metrics.vue`（运营指标 CSV 导入）**：`Lineage` 用三栏卡片表格清晰对比“配置映射 → 实测求值 → 设计规范”；`Metrics` 支持选择本地 `.csv` 文件读取文本或粘贴 CSV、表格化预览解析出的行列数据后再确认导入与触发 Mock 上报。
