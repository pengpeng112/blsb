## 2. 与原计划相比，必须纠正的口径

1. RT-01/02 已有成果要复用；RT-02 历史全量为 **958 passed / 8 skipped / 0 failed / 0 error**，
   不是本轮重新执行的结果。本轮相关后端局部 **100 passed / 1 skipped**，前端 **87 passed**。
2. `finish_job()` 的布尔值表示 fencing 更新成功，不表示业务已终结；不能为修调度而破坏 Operation 状态机。
3. 调度耗时定义为首次实际执行到最终结束，包含重试等待；首次 claim 刷新执行 deadline，重试不无限续期。
4. “昨日自然日”必须有真实 `[起点, 终点)` 查询边界；当前 `summary(days=1)` 是滚动窗口，改标题不算修好统计。
5. 医保 `debug-exchanges` 当前返回数组；分页改成对象要连同 API 类型、所有调用者和测试一起迁移。
6. 影子水位、已持久化待处理记录、已投递版本必须分开，禁止“读到即已发”。入库摘要与稳定源版本幂等键也要分开。
7. 导入计数包含“输入行”和“聚合业务记录”两个粒度，不能强凑 `rows_read = rows_applied + ...`。
8. 医保脱敏覆盖 request、response、validation_errors、note、审计、日志等全部持久化字段；校验器当前也会把值拼进错误文案。
9. 影像 CSV 有类型/长度/必填元数据，应提取并保留“未批准”状态；不能按旧计划全部当作来源未知。
10. 病理原文写“常见为 79 位”，可变段宽未固定。86 字符是该 79 位例子的 7 个分隔符展示形态，
    不能凭一个例子推断全局固定宽度，更不能默默补零或猜紧凑码分段。
11. 原“回滚到此版本”按钮缺少后端恢复语义，必须区分撤销某发布与基于历史快照恢复配置。
12. SSR、TestClient、多服务 HTTP、浏览器点击分别报告；静态路径存在只证明路由契约存在，不能承诺业务永不 404。

## 3. 验收边界

本批可完成：本地合成数据、临时库迁移、回归、真实 SQL 查询、本机回环 Mock、前端构建、SSR 和 API 契约验证。

第三方业务确认、生产部署。真实七天观察必须另行获得数据和运行授权；七天合成夹具只能证明工具可用。

验收逐项使用“实测通过 / 已实现未测 / 本地待修 / 外部阻断 / 不适用并附依据”。
新增测试数量是下限，必须同时满足场景表，不能以通过数代替覆盖与业务验收。
