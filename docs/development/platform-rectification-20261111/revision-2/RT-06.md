## 2. F01：脚手架连续扩展与失败原子性

1. 种子按 code 精确定位字典，再核对该字典 plugin_key；不能全文包含匹配，也不要求额外手写核心路由。
   可以使用Python AST定位 `_seed_rows()` 返回列表并保留源码格式，或专属可持续锚点；
   不用全文 `rfind('    ]')` 猜最后一个列表，不因全局SEED_MARK_BEGIN存在就拒第二业务。
2. 新业务都有专属标记/精确code判重，末尾插入锚点保留。同code同参数重放零字节变化；
   同code不同plugin拒绝且零写；已有业务只补缺失骨架，不覆盖已批准字段。
3. `--biz-dir` 是单层目录名，拒空值、首尾空白、`/`、`\`、`.`/`..`、盘符/UNC/绝对路径、
   Windows保留设备名/尾点/非法字符。最终每个输出目标 resolve 后验证在 workspace 相应根目录内；
   父路径含 symlink/junction 越界也拒绝，不能仅字符串检查后绕出根。
4. 校验所有参数/种子冲突/目标路径后再做写计划；dry-run不创建目录/文件/缓存、不改mtime。
   生成内容先在内存检查语法，seed_entry 中JSON的true/null不能原样变成非法Python字面量。
   失败不可留下已改种子却未建manifest的半成品；使用暂存与可恢复提交，清理仅限本轮临时目录。
5. 修 readme_path 使用实际 `数据上报/<biz-dir>/README.md`，不能仍指向 `数据上报/<code>/README.md`。
   标准骨架包括 manifest、summary/ledger占位与 `reg.attach('domain.routes', register_routes)` 的
   真实可导入实现；未知能力明确暂无数据，不返回伪成功。不自动加入生产插件加载集/启用发送。

验收：临时工作区连续创建两个不同目标A/B→各自注册/种子均可读取→再次运行A/B零字节变化；
已有第五业务复用；同code错plugin零写；Windows/Linux穿越和junction；dry-run零写；
插入锚点丢失/源语法损坏时拒绝，不写错位置。

## 4. F03：影像插件本地示范闭环

| GET `/api/v1/medins-imaging/datasets` | 数据集列表，真实代码/名称/revision/未确认计数，登录+target_scope |

## 5. F04：病理国家编码辅助的正确边界

只读根目录 `93ebd53751dc40669f4c977781904f8b.txt`，不得把其示例姓名/证件复制到代码和测试。
原文是8段、**常见为79位**：固定的是证件类型3、就诊类型1、时间14、机构12、类别1；
证件号码依证件类型填写，申请单号/病理号是院内原值，原文没有规定统一段宽。

新增纯函数，可沿用 `format_nhsa_pathology_index`/`parse_nhsa_pathology_index` 名称，但接口必须诚实：

1. 分隔格式按8段无损解析，校验已确认固定段和时间真实日历，前导零和原值保留。
   可变段仅按有来源的字符规则校验，不能为了79位补零、截断或硬限示例段宽。
2. format可输出紧凑串或分隔串。原字段给定时双向保留；任何输出都不能含未经来源支持的自动补位。
3. 紧凑串没有分隔符时，必须要求明确的可变段宽schema/原segments边界，或者返回
   `AMBIGUOUS_SEGMENTS`/`SEGMENT_WIDTHS_UNCONFIRMED`；仅总长79不足以推断分割。
   如添加“79位示例宽度Profile”，必须标EXAMPLE_ONLY且调用方显式选择，不作正式默认值。
4. 测试合成79紧凑/86分隔示例在显式schema下无损往返，另测非79的合法可变段分隔串，
   歧义紧凑串拒绝、坏日期/字符/段数/固定宽度拒绝、零前导保留。
5. 不修改既有encode返回结构、不放松CANDIDATE_UNCONFIRMED/B09门禁，内部病理号不补位。
   README明确：辅助解析通过不等于正式病理协议/真实PIS接入已验收。
