## 2. U01：先做逐页接口与权限盘点

为14个受影响页面列 method/path/真实请求字段/真实返回/角色/业务scope/理由/revision/审计，
核对后端路由与当前 TS API。形成同一份验收表写本轮交接，不建立另一套全局状态。

所有写操作统一具备：前端字段校验 → 禁重复提交 → 后端校验 → 成功反馈和局部刷新 →
失败保留输入/可重试 → 409 冲突不自动覆盖 → 审计可追溯。前端隐藏按钮不是授权边界，后端仍拒越权。
空列表、载入失败、部分失败、只读与禁用的原因都应明确显示，不能在 catch 返回空数组伪装成功。

## 3. U02：业务新建与编辑

- Targets 的新建按钮仅管理员可见。抽屉字段沿用 ReportTarget 实际字段：code/name/category/authority/
  plugin_key/mode/runtime_kind/owner_dept/readme_path 等，编码和枚举按服务端校验。
  plugin 下拉来自真实可用注册信息；如无元数据端点，可补受鉴权的只读元数据，不能杜撰“所有插件已支持”。
- TargetDetail 的配置编辑遵循 platform_admin/config_editor 与 target_scope。
  初始草稿复制服务端对象，保留 revision；409 提示并拉最新数据供对照，用户未保存输入不能静默丢弃或自动重试覆盖。
- 生命周期切 PILOT/PRODUCTION 必填理由（服务端同样校验并审计）；修改目录 lifecycle 不等于真实发送授权，
  唯一推送方、独立证据、真实链路门禁不松动。不得给药品生产路径接入 generic gate。
- readonly 字段与可编辑字段分开，extra 不因表单没展示就清空；表单未改的未知字段保留。
  保存成功更新页面和摘要，抽屉关闭后的脏输入有合理处理，避免切不同业务串表单。

## 4. U03：调度编辑与真实预览

新建默认停用，启停通过既有专用端点填写理由，PUT 不夹带 enabled 绕过审计。
镜像 observe_only 不显示新建副本/编辑执行参数/运行入口；服务端仍五路拒绝，不能靠 UI 限制代替。

表单包括 code/name/target/job_type/cron/misfire/concurrency/max_runtime/blackout/payload_template。
Job 类型使用真实 registry 类型；不能展示未注册类型让用户提交后才发现无处理器。
Cron 约300ms防抖预览5次，使用 RT-03 的院内时区显示；请求序号或 AbortController 防止旧响应覆盖新表达式。
非法表达式或范围外无触发显示真实原因，停止保存；组件卸载取消未完成请求和定时器。
blackout 提供增删行 HH:mm 编辑、跨午夜说明；payload JSON 非法阻止提交，保留输入与具体错误。
编辑带 revision，409 不覆盖；列表运行历史沿用 RT-03 分页、真实耗时与迟到信息。

## 5. U04：告警规则与通道

规则新建复用现有 RULE_FORMS 9类参数，区分 create/update 请求，code 创建后按后端能力只读。
校验数值范围、通道选择、全局/业务作用域；管理员与 config_editor 实际权限以 API 为准。
全局规则不向单业务scope用户泄露；改挂 target 必须保留 RT-02 的原/新双范围校验。

通道按 file/smtp/webhook 切换结构化表单，未知字段不默默丢失，内联秘密绝不进入状态快照/日志。
webhook 只 url_env、smtp 密码只 password_env；变量名校验使用 RT-03 后端规则。
smtp/webhook 清晰显示“本批不可启用/测试外发”，保存停用配置不等于启用；file 保留测试写入能力。
测试成功看真实 ok/error，不以 HTTP200 一律显示成功；失败仅显示脱敏错误与 request_id。
创建/编辑成功刷新对应行，保留规则/通道审计，通知日志分页继续可用。

## 6. U05：Mapping 可视化与无损高级模式

真实白名单为：`const, field, dict_map, concat, date_format, decimal_scale, regex_replace, null_fallback`。
旧计划的 `coalesce` 不是当前算子，禁止 UI 发明它。源参数为 `source_field` 等真实字段，不能用抽象字段名提交。

规则表支持 target/op/各算子参数、字典引用、增删与上下移动。字典下拉携带准确 revision/version 与批准状态，
无批准字典显示原因；不能选“最新”却在提交时漂移引用。
JSON→表格→JSON 保留字段、类型、顺序、空值、未知扩展键；不能直接展示的高级结构保留并提示切高级模式，
禁止只挑支持键重组后丢配置。非法 JSON/非法算子/危险 regex 提交前拦截，服务端白名单仍为最终防线。
现有映射 target 字段是否表示嵌套路径以引擎真实语义为准，UI 不承诺未实现的嵌套赋值。

模拟面板并列显示输入、输出、逐字段来源/字典命中/错误，调用现有 simulate，禁止前端伪造服务端试算结果。
“填入合成示例”有明确标识，不读真实患者记录；失败不清空上次输入。

## 7. U06：Pack 的差异与真实恢复语义

先修重复表达式 `p.content.pack_key || p.content.pack_key`，核对真实备用字段，避免随便替换为另一个不存在属性。
新增 DiffViewer：按JSON路径比较对象/数组，展示新增/修改/删除、旧新值、revision/digest，
类型变化可见，键顺序变化不制造伪diff，敏感配置值只显示安全摘要/环境变量名。

**当前 API `POST /config-releases/{id}/rollback` 只标记所选发布 rolled_back_at，不会恢复到它。**
本轮必须先确定并实现两种动作的真实边界：

1. 现有撤销语义的按钮叫“撤销此发布”，补必填 reason、同事务 AuditEvent，并保持旧调用兼容策略可审查。
2. 用户要求的“恢复到此版本”需要独立的 restore 行为：以该历史发布的不可变闭包为来源，
   校验本租户及引用可用性，创建新的发布/必要配置修订作为恢复结果，返回新 release_id/digest/来源版本。
   可新增 `/config-releases/{id}/restore` 等明确端点；不得把 rollback 的时间戳响应包装成恢复成功。
3. 恢复不能改写历史冻结包、已批准字典或删除新账；恢复前Diff、必填理由与确认，
   事务失败无半恢复，重复提交有幂等或显式冲突；含外部发送配置的恢复不得自动启用调度/发送。
4. 若现有模型无法安全表达完整恢复，本项保持本地待修，不得仅以改按钮文案宣称原“恢复到版本”目标完成。

表格化展示字典和版本条目，JsonViewer 展示剩余结构；API矩阵与架构/差异文档写清新语义。

## 8. U07：Workflows 防呆与 DAG

扫描并修复所有非法 JSON 被吞成空对象的位置，包括执行 context 的空 catch、节点 parameters 和导入DSL。
空白输入可按明示规则视作空对象，**非空非法内容必须报错并零POST**。不能只删旧任务书猜测的某行代码。
对保存、发布、执行、dry-run共用验证；错误提示定位节点/输入框，并保留用户原文。

DagGraph 用纯 SVG，不引包：拓扑分层，支持分支/汇聚/孤立节点、长标签、稳定坐标；
循环/重复节点/悬空边明确错误，不能死循环或悄悄丢边。后端 DSL 校验仍负责是否合法。
运行详情按 node_id 与真实 Step 状态着色，未知状态仍可见；等待不伪装成功，成功/失败/取消清楚区分。
图仅可视化，不改变 workflow 节点语义或生成额外执行请求。
