## 3. 目前视图正确到什么范围

主单复合身份为处方日期＋处方号＋药房；来源系统和业务类型另纳入程序身份。
码表关联保留`TRACE_BILLNO↔PRESC_NO`、`PRESC_DATE`、`STORE_CODE↔DISPENSARY`三项，避免仅按处方号跨日期/药房串单。
样本主从一致，加上已成功真实试报，支持本期正常门诊的使用结论。

当前正常分支要求：`PRESC_SOURCE=0 AND FLAG=1 AND DISPENSING_DATETIME IS NOT NULL AND NVL(REFUND_FLAG,0)=0`。
其他分支保留UNKNOWN，由质量门禁等待，**不是把所有OUT行直接报321**。
这些原始状态含义来自前轮实际源注释解码及既有契约；本轮验证定义和值分布，没有重新扩大为未知枚举的业务解释。

用户原SQL按`RECORD_ID`和`CREATE_TIME`分组；既有证据中RECORD_ID是记录主键，不能简单声称MAX必然吞掉不同记录的码。
原SQL主要缺点是以扫码记录代替业务整单、固定历史日期、没有明确药房/完成/退费状态和接口身份；现r10与程序已处理本期关键字段。
