### P2：发送器增加记录级父受理门禁

1. 定义依赖契约：`ex_lab_item.exLabId → ex_lab.id`，校验来源实例/租户/目标一致。共享调度器供main、reconcile、单子表和定向重放使用；本轮先实现检验依赖，其他业务仅兼容回归。
2. 子项准备发送前查对应父快照及当前版本的受理证据。当前批父尚未发送时先补查/发送该父；父04/网络未知/取数失败/必填不全/歧义时，相关子项进入PARENT_WAIT，绝不调用HTTP。
3. 父版本使用规范化payload摘要，排除每次刷新的operationTime和运行时间，绑定视图/映射revision。旧sent账只有id+opTime，不足以证明“修正后的父表”已受理：原账保持不变，必要时仅对当前待发送子项的对应父做定向重放并记录新摘要，禁止全库父表重发。
4. 顺序为父请求result=true → 持久化父受理证据 → 对应子请求。回执增加批次/run标识、单调序号、带时区高精度请求起止时间、父ID/父摘要及子ID，不记录原始敏感payload。父证据持久化失败即停止其子项；HTTP超时按未知处理，幂等重试父后再子。
