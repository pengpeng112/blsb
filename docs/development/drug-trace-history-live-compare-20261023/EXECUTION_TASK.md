## 一、用通俗话说明当前问题

历史Excel里的“单据号”实际按原SQL来自扫码明细的PRESC_DETAILID；现系统上传的是由业务主单聚合的整单。历史明细号和新系统稳定上传单号不是同一字段，不能直接拿两个单号比较后认定漏报。

当前视图先把扫码记录关联到发药主单：

```text
DRUG_USER.MED_TRACE_RECORD T
  TRACE_BILLNO = TO_CHAR(M.PRESC_NO)
  PRESC_DATE   = M.PRESC_DATE
  STORE_CODE   = M.DISPENSARY
PHARMACY.DRUG_PRESC_MASTER M
```

三项关联用于防止不同日期/药房的相同处方号串单。若某类历史扫码记录关联不上当前主单，内连接视图看不到它；这是待查的一种可能，尚未证明全部未匹配都因此产生。
本期正常发送还要求`PRESC_SOURCE=0 AND FLAG=1 AND DISPENSING_DATETIME IS NOT NULL AND NVL(REFUND_FLAG,0)=0`。全退/退费进入UNKNOWN，当前不能按普通发药发送。
