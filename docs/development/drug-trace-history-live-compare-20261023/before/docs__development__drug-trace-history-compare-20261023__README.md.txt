## 2. 比对口径

既有原SQL将PRESC_DETAILID作为单号、CREATE_TIME作为单据时间；现视图source_line_id来自同一明细标识，source_bill_id则是处方日期/处方号/药房复合键，bill_time来自发药时间。文件是否完全沿用该映射还需少量真实样本确认，不能直接拿历史单号对现主单号、或把扫码时间对发药时间判“不一致”。

多数历史单号有日期前缀，5077行不符合日期解析模式；可解析日期最早2026-03-08，比文件时间最多早196天。这里只是字符串模式观察，未认证前缀业务含义；后续先按精确明细号探针确认真实主单时间，不能机械只查文件日期范围后把所有范围外记录当缺失。

比对需保留出现次数，分别记录：历史有/视图无、视图有/历史无、同单码数或分组差异、时间差异、当前删除/业务状态变化、未能确认。双方齐套范围未落实前，不能因总数相同就宣布一致。
