## 2. 具体实施步骤（必须逐项完整实现）

### 步骤 1：修复外部导入器三大硬伤并补齐 13 表完整分类

打开 `implementation/plugins/external_ledger/importers/inf_pusher.py` 与 `plugins/domains/infectious/hooks.py`：

1. **修复 8 小时时区错位（`inf_pusher.py`）**：
   - 真实环境中，容器产出的 `receipts-YYYYMMDD.jsonl` 行内 `ts` 为 **UTC**，而 `sent.jsonl` 的 `opTime` 与 `watermark.json` 的水位值为 Oracle 源端 **CST（东八区）**！
   - 扩展 `import_files(..., source_tz="", receipts_tz=None, sent_tz=None)`：
     - 向后兼容旧调用：若仅传 `source_tz`，按 `source_tz` 作为回退；新增 `source_tz="AUTO_MIXED"`（以及显式 `receipts_tz="UTC", sent_tz="CST"` 参数），让 `receipts-*.jsonl` 的 `ts` 按 `receipts_tz`（默认 `UTC`）解析、而 `sent.jsonl` 的 `opTime` 与 `watermark.json` 按 `sent_tz`（默认 `CST`）解析！前端 `ImportPane.vue` 默认选中推荐项 `标准生产混合口径（回执 UTC + 源数据北京时间 CST）`，彻底根除 8 小时偏差！
2. **修复 `parent-wait` 被误判为 `REJECTED` 的严重失真（`inf_pusher.py:85-102`）**：
   - 在 `classify(rec)` 中显式识别 `if stage == "parent-wait": return "PARENT_WAIT", "PARENT_WAIT"`；
   - `_RESULT_TO_BUCKET["PARENT_WAIT"] = ("PENDING", "PARENT_WAITING")`（归入待处理/等待父受理，**绝不再归入 `REJECTED` 被拒桶！**）；
   - 同时保留并单列 `CLIENT_INVALID`（必填未过尾差）与 `last_error_code`（`01`/`02`/`03`/`04`/`05`/`99`）。
3. **补齐全部 13 张上报接口的中文名称与标准文书映射（消灭“其他/未分类”黑洞）**：
   - 在 `inf_pusher.py` 与 `infectious/hooks.py` 中完整对齐 13 张表（表 key → 接口编码/端点 → 中文名 → 主表依赖）：
     1. `admission` → 住院病案首页/诊疗记录（`emrAdmissionRecord`）
     2. `admission_info` → 入院记录（`emrAdmissionInfo`）
     3. `discharge_info` → 出院记录（`emrDischargeInfo`）
     4. `death` → 死亡医学证明/记录（`emrDeathInfo`）
     5. `first_course` → 首次病程记录（`emrFirstCourse`）
     6. `daily_course` → 日常病程记录（`emrDailyCourse`）
     7. `exam` → 检查报告主表（`emrExClinical`）
     8. `exam_item` → 检查报告项目明细（`emrExClinicalItem`，依赖 `exam`）
     9. `ex_lab` → 检验报告主表（`emrExLab`）
     10. `ex_lab_item` → 检验报告项目明细（`emrExLabItem`，依赖 `ex_lab`）
     11. `order` → 医嘱处方主表（`emrOrder`）
     12. `order_item` → 医嘱药品明细（`emrOrderItem`，依赖 `order`）
     13. `vital_signs` → 生命体征记录（`emrVitalSignsRecord`）
   - `hooks.classification()` 必须逐行返回 **全部 13 张表**（含零值行，附带每张表的 `parent_table`、`watermark`、`lag_hours`、`parent_waiting`、`client_invalid`、`accepted`、`rejected`、`retryable`），仅未知第 14+ 表才进“未登记其他表”。

### 步骤 2：实现多快照解析与 GB 级目录只读流式增量同步器（`monitor_sync.py` + 监控 API）

1. **新增持久化观测快照表（编号迁移 `024` 或当前顺延编号，SQLite + PG 双兼容）**：
   - `infectious_table_telemetry`（按 `tenant_id + source_instance + table_key` 唯一）：存每张表的最新 `watermark_op_time`、最近班次 `last_shift_at / shift_rows / shift_sent / shift_parent_wait / shift_skipped_invalid / shift_failed / shift_truncated / shift_error`、最近日终对账 `reconcile_day / reconcile_repushed / reconcile_parent_wait / reconcile_failed`。
   - `infectious_watchdog_snapshot`（按 `tenant_id + source_instance` 唯一）：存 `status.json` 快照（`checked_at`, `host_label`, `overall_level`, `checks_json` 含 `C1–C11`, `relay_reachable`, `driver_errors_json`）、最新晨报 `daily_ymd / daily_text`、近期守护告警列表 `recent_alerts_json`（全部经 `redact_text` 脱敏校验，零患者字段）。
   - `external_file_cursor`（按 `tenant_id + target_code + source_instance + file_name` 唯一）：记录流式尾读偏移 `(file_size, byte_offset, head_sha256, updated_at)`。
2. **支持解析全部状态快照文件（浏览器导入与目录只读同步共用同一套解析器）**：
   - 当文件名为 `watermark.json`、`last-run-real.json`、`last-run-reconcile.json`、`reconcile-YYYYMMDD.json`、`pending-wait.json`、`status.json`、`daily-YYYYMMDD.txt`、`alerts-YYYYMMDD.jsonl` 时，不再走单行 JSONL `_read_lines` 报错 `NOT_JSON`！而是作为完整 JSON/文本安全解析（校验大小上限与白名单键，丢弃任何未知或疑似患者身份字段）写入上述两张遥测快照表！
3. **实现受控目录只读流式增量同步器 `plugins/domains/infectious/monitor_sync.py`**：
   - 通过环境变量 `BLYB_INF_PUSHER_STATE_DIR`（如生产 compose 内 `/data/exchange/inf-pusher/state`）与 `BLYB_INF_WATCHDOG_STATE_DIR`（如 `/data/exchange/inf-watchdog/state`）读取路径；未配置时优雅返回 `{"configured": false, "reason": "未配置实时状态挂载目录，当前展示导入副本数据"}`，绝不报错 500！
   - 对 `receipts-YYYYMMDD.jsonl`（只扫近 3 天文件）与 `sent.jsonl` 采用**按字节偏移流式逐行读取（每次最多处理可配置行数如 50,000 行并保存游标，只在遇到完整 `\n` 结尾行时推进偏移，防止读到推送器写了一半的尾行；若文件头 SHA256 变化说明轮转重建则从 0 重读）**，内存占用恒定 `< 30MB`，即使面对 855 万行 1.2GB 回执文件也能稳健增量吸收！
4. **挂载传染病专属只读监控路由 `plugins/domains/infectious/routes.py`（通过 `reg.attach("domain.routes", register_routes)`，强制 `p.require_target_scope("inf_cdc_frontend")`）**：
   - `GET /api/v1/infectious/monitor/overview?days=7&source_instance=`：返回总览卡片指标（`accepted`、`parent_waiting`、`rejected_contract`、`client_invalid`、`retryable_unknown`、`observed_until`、`last_shift_at`、`watchdog_level`、`wecom_relay_ok`、`sync_configured`、每日趋势序列、错误码 `01/02/03/04/05/99` 聚合分布并附中文含义）。
   - `GET /api/v1/infectious/monitor/tables?days=7&source_instance=`：返回按主子拓扑分组的 **13 张上报接口完整状态矩阵**。
   - `GET /api/v1/infectious/monitor/watchdog?source_instance=`：返回 `C1–C11` 体检卡片详情、近期企微/本地告警记录、最新 `08:00` 晨报全文。
   - `GET /api/v1/infectious/monitor/reconcile?days=7&source_instance=`：返回日终对账记录 + 调用 `reconcile_shadow` 生成平台影子 vs 外部台账的 7 类差异对比汇总。
   - `POST /api/v1/infectious/monitor/sync`（`operator` / `platform_admin`）：触发一次只读目录增量同步并返回新增行数与快照更新时间（未配置目录时温和提示，不抛 500）。
