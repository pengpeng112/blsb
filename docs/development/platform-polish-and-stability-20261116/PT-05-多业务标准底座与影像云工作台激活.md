## 2. 具体实施步骤（必须逐项完整实现）

### 步骤 1：建立统一的三大标准多业务遥测钩子（让所有当前与未来业务说同一种语言）

打开 `implementation/plugins/domain_hooks.py` 与 `apps/core_api/report_target_routes.py`：

1. **升级 `TargetSummary` 双口径支持**：
   - 在 `TargetSummary` 数据类中新增可选字段（带默认值保持 100% 向后兼容）：
     - `primary_bucket: str = "CONFIRMED"`（取值 `"CONFIRMED"` 或 `"ACCEPTED"`：两步回执确认型业务如码上放心为 `"CONFIRMED"`；同步接口受理型业务如传染病、影像云示范为 `"ACCEPTED"`）；
     - `last_accepted_at: str | None = None`（最近一次平台/前置机受理时间）。
   - 为 **`plugins/domains/medins_emr/hooks.py`（新建！）** 实现 `HOOK_TARGET_SUMMARY`：基于 `DebugExchange`（联调校验/Mock/人工回填记录）输出联调就绪度与近 N 天演练统计（`evidence_kind="mock"`，明确标注 `联调演练统计（尚未切入正式医保网关）`），彻底消除驾驶舱和详情页上山东医保一直显示 `"暂无数据"` 灰卡的问题！
2. **新增标准钩子 `HOOK_TARGET_STREAMS` 与路由 `GET /api/v1/report-targets/{code}/streams?days=7`**：
   - 任何医院上报业务几乎都由多张子表/数据集/交易组成。统一返回结构：
     ```json
     {
       "target_code": "...",
       "stream_kind_label": "临床文书视图 | 医保交易 | 影像数据集 | 业务单据类型",
       "items": [
         {
           "code": "APPLY_INFO",
           "name": "检查申请单数据集",
           "group": "申请与报告",
           "depends_on": null,
           "field_count": 24,
           "watermark": "2026-11-16T09:30:00+08:00",
           "lag_hours": 1.2,
           "accepted": 15,
           "confirmed": 0,
           "rejected": 0,
           "waiting": 0,
           "status": "OK",
           "note": "r2-csv16 · 合成投影正常"
         }
       ]
     }
     ```
   - 为五大业务全部接通 `HOOK_TARGET_STREAMS`：
     - `infectious`：复用 `PT-03` 的 13 张文书视图遥测；
     - `medins_emr`：返回 **23 个山东医保交易（`11401`～`12604`）** 的字段数、待确认路径数、最近校验/Mock/回填次数与结果；
     - `medins_imaging`：返回 **16 个济南影像云数据集（`APPLY_INFO`～`SETL_INFO`）**（补齐全部 16 个数据集的准确中文业务名称映射，如 `APPLY_INFO=检查申请信息`、`STUDY_INFO=检查登记信息`、`SERIES_INFO=影像序列信息`、`IMAGE_INFO=影像实例信息`、`RPT_INFO=诊断报告信息`、`SETL_INFO=医保结算关联信息` 等！）及各数据集冻结/Mock 投影计数；
     - `drug_trace`：只读汇总门诊发药、住院发药、退药等单据分类计数；
     - `pathology`：只读汇总病例、玻片、扫描、索引、视图发布计数。
3. **新增标准钩子 `HOOK_TARGET_HEALTH` 与路由 `GET /api/v1/report-targets/{code}/health`**：
   - 统一返回业务接入与运行健康检查项数组 `checks: [{code, name, level: "OK"|"WARN"|"CRITICAL"|"INFO", detail, action_hint}]`：
     - 通用基础检查（所有业务自动具备）：① 业务生命周期与唯一推送方状态（`sole_pusher`）；② 关联目的地配置状态（是否绑定、Mock 还是正式、网关配置完整性）；③ 关联调度任务状态（启用/停用/最近一次运行成败）；④ 未关闭告警计数；
     - 插件专属检查：传染病附加 `inf_watchdog` 守护新鲜度与企微通道状态；山东医保附加签名算法待确认项 `SIGNATURE_UNCONFIRMED` 提醒；济南影像云附加 77 处 `SPEC_FIELD_CONSTRAINT_PENDING` 待院方/医保核定提醒；病理附加 `B01–B09` 阻断摘要。

### 步骤 2：打通 `RESEND_ALLOWED` 受控重发与死信任务（DLQ）管理闭环

1. **修复 `RESEND_ALLOWED` 人工处置后的孤儿状态（`plugins/report_ledger.py` + `apps/core_api/report_target_routes.py`）**：
   - 当前管理员将 `UNKNOWN` 提交人工裁定为 `RESEND_ALLOWED` 后，`Submission.state` 回到 `PREPARED`，但没有任何安全入口触发重发！
   - 新增受控端点 `POST /api/v1/report-center/ledger/{target}/{submission_id}/requeue`（要求 `operator`/`platform_admin` + `require_target_scope(target)` + 必填 `reason` ≥5 字）：校验该 `Submission` 当前确为 `PREPARED` 且已有人工处置记录；若绑定非 Mock 目的地则必须通过 `assert_target_can_send_real` 闸门；通过后安全执行重投递或入队标准 `target.send_prepared` worker 任务并记 `AuditEvent`！
2. **新增死信任务（耗尽重试 `FAILED` Job）只读巡检与受控重驱（`ops_routes.py` + `Schedules.vue`）**：
   - 新增 `GET /api/v1/ops/dead-letter-jobs?target_code=&limit=50` 与 `POST /api/v1/ops/dead-letter-jobs/{job_id}/redrive`（必填理由，重置尝试次数创建新排队任务或安全唤醒，记审计）；
   - 在 `Schedules.vue` 增加「异常死信队列」页签，运维无需进数据库即可查看失败原因并一键审计重驱。
