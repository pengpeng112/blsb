# 实施任务、测试与交付标准

版本v0.4，2026-09-30。本章保留T01—T15任务标识便于追溯，实际执行顺序及首院新增要求以第9—12节为准；10章提供连接器与质量规则的具体契约。不要按旧版“泛化DB驱动”范围遗漏SQL Server/Oracle及条码反查。

## 1. 实施原则

按纵向闭环交付，每阶段都有可运行结果。先做可恢复字节归集，再做病理关联和可视化流程，随后适配真实外部平台。首期不同时实现所有数据库驱动、所有WSI解码和所有医保协议。

生产上报的等待项仅阻断对应外部契约，不能成为不做本地MVP的理由。所有Mock、草案Profile和未实现适配器显著标识；测试环境和生产目标分开配置。

## 4. 测试矩阵

| 编号 | 场景 | 必须断言 |
|---|---|---|
| A01 | 单个500MB以上及50GB合成文件 | 流式内存稳定；结果大小/hash一致 |
| A02 | 传片成功但ACK丢失 | 重传同片幂等，不重复累计进度 |
| A03 | 同一片索引传不同字节 | 409/422且旧已确认片不覆盖 |
| A04 | 服务进程在每个提交阶段被杀 | 按03恢复，无虚假成功或无主永久泄漏 |
| A05 | 低磁盘、多会话并发预留 | 超配阻断且保留安全空间，不写爆系统盘 |
| A06 | 同路径同名新文件、原地修改、复制中断 | 不沿用旧snapshot/hash或错误绑定扫描 |
| A07 | 主文件先到、伴随目录晚到 | Bundle未齐不得提交 |
| A08 | 路径穿越、重解析点、大小写碰撞 | 服务端与Agent均拒绝越界和冲突 |
| A09 | 凭据吊销、跨租户asset/session访问 | 拒绝且不泄露对象存在性/数据 |
| A10 | Range、HEAD、If-Range、无效范围 | 符合HTTP语义并且下载授权不绕过 |
| B01 | PIS先到/文件先到 | 都能最终关联，不丢输入 |
| B02 | 两医院/两来源/跨年同病理号 | 不串病例；来源域显式 |
| B03 | 一病理号3片，其中一片重扫 | 3张玻片、4次扫描，不显示4张玻片 |
| B04 | 预期3片，到2片＋一片重复 | 不判齐套 |
| B05 | 患者姓名相同但ID不同 | 不自动合并 |
| B06 | 原文条码、PIS、HIS冲突 | 隔离复核，原始证据保留 |
| B07 | 身份/机构/类别更正 | 新索引/包/提交版本，历史不可变 |
| B08 | 正式索引与草案字典混用 | Schema/Profile测试阻断；79/86示例正确 |
| C01 | 同一source事件重复10次 | Inbox/业务结果幂等，记录尝试可追溯 |
| C02 | 轮询同时间戳跨页＋补录＋删除 | 无漏数，窗口重读和盘点有效 |
| C03 | 旧租约Worker在超时后返回 | fencing阻止旧结果覆盖新状态 |
| C04 | 流程有环/端口不兼容/缺字典 | 发布前失败并定位节点 |
| C05 | 映射中出现代码执行/网络/无界正则 | 拒绝或限时，不执行任意代码 |
| C06 | 配置发布时旧任务仍运行 | 旧任务保持旧版本，新任务用新版本 |
| D01 | API超时但对方已受理 | UNKNOWN→查询，不能新建重复业务提交 |
| D02 | 重复/乱序/部分回执 | 逐项幂等；旧回执不回退新版本 |
| D03 | 文件未复制完成就准备发布 | 外部视图不可见 |
| D04 | 交换库已提交核心库未收到结果 | 按generation查证恢复，不重复发布 |
| D05 | 对方跨多次查询遇到新发布 | 按约定snapshot/父子重读处理；若无方案明确失败限制 |
| D06 | 对方完整下载但无业务回执 | 显示“已下载/待确认”，不显示医保成功 |
| D07 | 退款、作废、报告追加、补片 | 正确墓碑/更正，未过保留期不删文件 |
| D08 | Profile字段超长/未知格式 | 阻断，不截断或随意改扩展名 |
| E01 | 控制台查看原始敏感值 | 权限限制且审计 |
| E02 | 首次离线安装、服务自启、证书到期 | 有可执行手册与清晰失败提示 |
| E03 | 从备份恢复DB、文件、配置和密钥 | 关联与提交证据可用，孤立引用被检出 |
| E04 | 加入无患者的metrics业务 | 通用内核不改，流程和回执仍可运行 |

必须用真实授权WSI样本验证厂商格式。合成大文件只测试传输和存储，不证明病理图像可用。若转换为DICOM，另验文件头、金字塔、像素、方向、颜色及目标查看端，不只检验扩展名。

## 5. 性能与容量记录模板

记录工作站型号、扫描软件、磁盘、服务器CPU/内存/卷、网络、TLS配置、文件大小分布、并发、扫描是否同时运行、处理器版本。分别测源读、Agent hash、院内传输、服务器合并/hash、交换复制、目标读取。

验收报告给P50/P95耗时、峰值RSS、CPU/IO、重试恢复耗时和磁盘峰值，而非只给一个平均速度。存储容量按原件、重扫、派生、并发暂存、交换副本、备份和保留期估算，明确GB/GiB单位。

建议试点先覆盖持续运行一个完整业务周期及一次模拟长时间断网，再扩大设备数量。实际稳定性观察时长与医院约定，不把一次上传成功当生产验收。

## 6. 部署、升级与运行手册

服务器提供离线容器包或受支持系统服务包，包含依赖镜像、校验和、迁移、初始化、证书配置、healthcheck、备份/恢复、日志路径。Windows Agent提供签名安装程序或经医院批准的安装方式，配置服务账户、开机启动、故障重启、ACL、证书和卸载保留策略。

升级先备份配置/元数据，数据库采用expand-contract兼容迁移；任务和资产保持可恢复。回滚应用不能自动倒退外部平台提交，也不能盲目回滚数据库破坏新数据，需按迁移兼容矩阵处理。

上线监控至少包括：设备离线、最老未处理时间、源系统连接异常、磁盘预留不足、checksum失败、持续身份冲突、交换网关不可达、Profile拒绝、UNKNOWN增长、备份失败和证书即将到期。

## 7. AI开发工作方式建议

给实施AI的起始指令：先阅读00—07及09/10、检查契约样例，按第9节输出阶段A/B实施清单并建立可运行闭环；所有未知外部接口采用显式Mock并登记阻断，不自行编造。每完成一任务，更新实现矩阵：已实现、自动测试通过、现场待验证、未实现。

每次交付包含代码改动、接口变更、数据库迁移、执行过的测试和未通过项；“页面完成”和“链路完成”分开。不要用固定假数据或始终返回success通过验收；UI看到的状态必须来自持久任务与证据。

## 8. 第一版可演示的完成定义

在两台测试机器或隔离环境中，扫描输出模拟器生成3张玻片及一次重扫；Agent自动采集，在上传中人为断网并恢复；服务器校验保存；导入PIS/HIS模拟记录并精确关联；UI正确显示缺片/齐套及版本；生成索引候选与冻结包；分别执行HTTP Mock提交和视图＋HTTPS供采集；模拟回执与无回执两种结果；随后追加报告，产生更正版本；最后从备份恢复并对账。再运行metrics CSV场景验证通用性。

达到上述结果可称“平台MVP闭环完成”；只有真实设备、真实PIS/HIS和正式平台分别通过现场验收，才可称“病理医保生产接入完成”。

## 9. v0.4 开发阶段与退出条件

### 阶段A：工程与首院契约锁定（T01、T02、T06a）

交付：模块化仓库、可重复依赖锁、PostgreSQL迁移、身份权限、配置版本/secret_ref、统一错误、日志脱敏、测试环境、最小控制台；同时建立PIS/HIS合成数据和连接器SDK，禁止先搭大量空页面再补业务。

T06a拆出首院适配器能力接口、SourceScope、字段血缘、查询模板注册、候选数组、raw行快照及质量问题接口。来源字典未批准也能执行Mock。提供首院配置向导：数据库类型/对象选择→字段映射→样本脱敏预览→候选冲突/质量检查→批准版本→启用；未批准项清晰显示。

退出：全新开发环境能一条文档命令启动，迁移可重复；有效/无效配置校验、跨租户、无凭据脱敏、参数化查询编译和三类条码候选契约通过。真实DB驱动待连接须显式标注，不能只写接口函数即视为完成。

### 阶段B：自研文件链路（T03、T04及最小设备/文件UI）

交付：Windows Agent服务及SQLite持久队列、模拟扫描器、重启盘点、人工完成证据入口；独立Storage API/worker、磁盘预留、固定分片续传、服务端hash、不可变文件、Range读取、提交意图恢复；UI显示设备、文件与失败原因。

首院演示事件只含条码900001，不必含病理号，不调用HIS也能完成字节归集。原件与缩略图、报告附件分role；不依赖WSI解码器完成原件传输。扫描完成语义按03/06验证。

退出：B阶段必须实测500MB以上文件及可配置大文件压力；50GB测试放在足够磁盘的专门性能任务，资源不足如实记未执行，不能伪报通过。断网、ACK丢失、进程重启、分片冲突、源变化、低磁盘和提交故障点恢复通过；Windows服务自启需Windows环境证据。

### 阶段C：真实库形态的病理闭环（T05、T06b、T07、T09）

交付：工作流租约/Outbox/Inbox、SQL Server/Oracle适配器实现、条码反查、本院字段映射、身份/就诊决策、日期/类别/机构/状态质量门禁、报告/玻片修订、索引、冻结包和人工处理台。保持插件化，核心不引用Pitaya表名。

T06b必须实现创建时间新增通道与分区内容盘点，并在UI显示覆盖能力。没有真实数据库时在合成仓储执行合同测试，并提供方言集成测试入口；对真实驱动的验证状态单独列出。禁止自动连接报告中的地址寻找凭据；使用已有授权测试连接时，只执行批准的受限只读模板。

退出：新增F01—F20用例按实现阶段执行；三片一次重扫、条码歧义、前导零、文件先到、身份冲突、同患者多就诊、未来日期、未映射字典、历史修改及缺失候选均可在UI定位。未确认字段只能进入等待；另用明确批准的合成规则跑成功路径，不能把所有记录阻断当业务已完成。

### 阶段D：可视化配置与通用交换（T08、T10、T11、T12）

交付：连接器配置表单、字段映射预览/血缘、字典版本、有限DAG画布、发布/回滚与dry-run；HTTP Mock交换、独立交换库发布+HTTPS、回执/对账页；PACS草案字段投影及问题列表；metrics CSV第二领域。

范围：首版输入实现目录/完成清单、HTTP事件、CSV、首院SQL Server/Oracle；输出实现HTTP Mock及数据库视图+HTTPS参考。SFTP、DICOM收发、其他HIS品牌、厂商SDK解码保留明确插件契约及未实现状态，不需要一口气实现。界面不能把未实现选项显示成可用。

退出：操作者可通过页面新建连接器配置、保存映射、模拟、发布流程、执行并查失败；新增metrics不改核心传输/任务表；同包双目标互不覆盖；下载无回执不显示医保成功。新实例安装文档、现场阻断清单和用户手册齐备。

### 阶段E：可靠性与发行（T15；此前每阶段也要保持可启动）

交付：固定版本离线依赖/镜像、Windows安装与服务脚本、服务器安装、升级兼容矩阵、迁移、备份恢复、告警、授权、容量压测记录、SBOM/许可证。离线包实际构建/验证与“只提供脚本”分别说明。

退出：清洁环境部署、断网重启、数据库/文件一致恢复与对账演练通过；记录实际硬件、耗时、峰值内存/磁盘、失败恢复，不以空报告代替结果。至此可标“本地MVP验收通过”，不标生产接入成功。

### 阶段F：真实医院及外部平台（T13、T14）

按09的B01—B09逐项取得证据：先授权只读核验PIS/HIS，再厂商真机采集，再医保测试通道，最后按医院流程启用生产。每种来源/目的地独立批准，不因Mock已通自动解锁。现场不能推进时继续其他可独立工作，不虚构生产结果。

| F08 | HIS类型空/脏值，只有格式正确号码 | 候选建议，默认仍等待；批准回退后另测适用边界 |
| F09 | 未来申请时间、错误日期、仅CreateTime | 质量阻断，不从申请号或当前时间纠正 |
| F10 | 边界时钟容差、出生未知、外院会诊原报告 | 固定评估时间；只应用语义相符规则，不拼造生日 |
| F11 | 类别'--'、FreezingID存在但规则未批准 | 等待，不默认常规，不自行推断类别 |
| F12 | 医保机构码缺失、扫描/报告机构不同 | 等待或使用批准报告机构映射，不套扫描单位 |
| F13 | 打印状态为0/512等未知值 | 不认定已扫描、报告审核完成或病例齐套 |
| F14 | 旧病例报告变化但CreateTime不变 | 分区盘点发现新修订；增量覆盖不虚报完整 |
| F15 | 盘点中断、权限异常、一页缺行 | 不误删；完整覆盖标记不可生成 |
| F16 | 经确认源作废及追加报告 | 新版本/墓碑候选，历史冻结内容不变 |
| F17 | 只有V_PIS_IMAGE JPG及报告URL | 不宣称WSI已取得；附件role正确 |
| F18 | QPIS/PITAYA同键及来源迁移 | 不双读合并；namespace映射与迁移审计 |
| F19 | UI更正与另一个操作者并发、历史提交已存在 | If-Match冲突；授权决定与新包可追溯 |
| F20 | 仅安装metrics插件及CSV输入 | 病理字段非核心必填，HTTP Mock可闭环 |

这些用例的机器可读实施清单见 `契约与示例/first-hospital.acceptance-cases.json`。该文件是验收规范，不是自动化测试代码；实施AI必须把场景转成真正的测试、SQL夹具和端到端操作，并提交执行证据。

## 11. 容量与现场验收补充

报告给出的19,357例、约71例/日只用作首轮采样参考，不是生产容量承诺。采集不少于院方约定的代表性业务窗口，统计工作日/峰日病例、每例玻片P50/P95、每片字节、重扫率、晚到文件、单日峰值、长断网积压与保留期。

计算至少包含：日原件量=每日病例×每例实际扫描片数×每片平均字节×重扫系数；容量另加派生、副本、交换区、备份及保留期；暂存预算按并发分片+完整合并双份+安全余量；可用带宽按实际传输窗口与峰值积压恢复时间测算。各变量必须来自测量或清楚标注假设，不能拿日历平均代替工作日峰值。
